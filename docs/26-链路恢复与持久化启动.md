# 26 · 链路恢复与持久化启动

> 时间：2026-10-02 20:58
> 现象：设备屏幕提示「无法连接服务，请稍后再试」

## 一、结论先行

**根因一句话：后台服务没在运行，不是设备故障、也不是网络问题。**

设备侧一切正常：COM3 在位、固件正确（`ELF SHA256: 5be30c4d0`）、Wi-Fi 连上 `HW-ZooKeeper`、后台机 IP 仍是 `192.168.3.139`（固件里 OTA 地址 `http://192.168.3.139:8003/xiaozhi/ota/` 编译期写死，**没漂**）。

## 二、排查路径

| 检查项 | 结果 |
|---|---|
| 8000 / 8003 / 8004 / 8005 | **全部 closed** ← 病根 |
| COM3 串口 | 在位（VID_303A&PID_1001） |
| 后台机 IPv4 | `192.168.3.139`，与固件配置一致 ✅ |
| 投递箱目录 | inbox/done/announced 齐全 |
| `/notify/status` | 连接被拒（服务没起） |

## 三、走的弯路 & 新解法：脱离会话启动

历史上服务总是"起完就没了"——原因是我从 AI 会话里用普通 `Popen` 拉起的进程，**回合结束会随整棵进程树被回收**。

这次改用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`（失败再叠加 `CREATE_BREAKAWAY_FROM_JOB`），让进程**脱离父进程树**，不再随会话回收。

**新增工具：`tools/start_services.py`**

```bash
python tools/start_services.py            # 启动（含等待+复查）
python tools/start_services.py --status   # 只查端口
python tools/start_services.py --stop     # 按 _logs/pids.json 停
```

- 日志落到 `server/_logs/server.out.log` / `admin.out.log`
- 幂等：已在监听的端口自动跳过
- 环境处理：自动注入 ffmpeg PATH、`PYTHONUTF8=1`，并**剥掉 `MSYSTEM`**（ESP-IDF 老坑）
