# 36 · "老是断开服务器连接" = 设备一直在重启（惊讶动画栈溢出，10240 都不够）

> 2026-10-03 02:50 定位，02:53 刷机修复，ELF SHA256 `ca46af353` 验机通过。

## 1. 现象

服务端日志里"设备上线"**每 1~8 分钟一次**（01:57~02:31 共 11 次），
但"客户端断开连接"**一次都没有**。

```
01:57:41 设备上线    01:58:10 设备上线    02:01:20 设备上线
02:02:46 设备上线    02:03:42 设备上线    02:05:20 设备上线
02:13:14 设备上线    02:20:26 设备上线    02:25:30 设备上线
02:27:22 设备上线    02:31:13 设备上线
```

## 2. 破案关键：OTA 请求 = 开机

> **`grep "OTA请求设备ID" server.log` —— OTA 请求只在设备开机时发生。**

上线次数 ≈ OTA 次数 ⇒ **不是"断线重连"，是设备在一次次重启**。
（真断线的话服务端一定会有"客户端断开连接"日志，这里没有。）

## 3. 真凶

`firmware/device_dump/serial_final.log`：

```
I (224810) EmojiController: 已发送动画消息，类型: 4
I (224820) EmojiController: 执行惊讶表情动画

***ERROR*** A stack overflow in task AnimationTask has been detected.

Backtrace: 0x40381bd1:0x3fcc8270 0x40381b99:0x3fcc8290 0x40382b02:0x3fcc82b0
           0x4038418e:0x3fcc8330 0x40382c08:0x3fcc8350 0x40382bfe:0x00000000

ELF file SHA256: a8204da07
Rebooting...
```

⚠️ **重点**：`a8204da07` 就是**栈已经从 4096 改成 10240 之后**的固件
（见 `docs/33`）—— 也就是说 **10240 仍然不够**。

原因在 `ExecuteSurpriseAnimation()`：它调 `lv_refr_now(NULL)` 做**同步全树刷新**，
LVGL 9.3 这条调用链（刷新 → 布局 → 绘制 → 刷新驱动 → I2C）比预想深得多。

## 4. 修复

`main/boards/esp32-s3n16r8-emoji/emoji_controller.cc` **两处** `xTaskCreate(AnimationTask...)` 的栈：

```
10240  →  16384
```

- `Initialize()`（约 45 行）
- `InitEmoji()`（约 3196 行，重建任务的分支）

**改完必须 `grep -n 16384 emoji_controller.cc` 确认两处都改到**，只改一处的话
从 `InitEmoji()` 那条路径起任务时还会溢出。

已重编（44s）+ 刷入 ota_1（不动 ota_0）+ 验机：
串口启动日志 `ELF file SHA256: ca46af353` = 本地 `ca46af353` ✅。

## 5. 影响链（为什么它会伪装成"播报没声音"）

```
播报 / AI 回复 → 情感判定为"惊讶" → 惊讶动画 → 栈溢出 → 设备重启
   → 声音播一半没了 / 屏幕卡住 / 服务端显示"断开连接"
```

主动播报之所以"一句都听不到"，是 **docs/34（ContentType）+ docs/35（tts/start）+ 本篇（栈溢出重启）**
三个 bug 叠在一起，每修一个都看不到效果。

## 6. 待验证

惊讶动画（动画类型 4）由 **LLM 回复里带惊讶情感标签** 触发，直接投文本的主动播报不会带，
所以本次没能在实验室条件下复现触发一次。已连续观察 90 秒无重启、无 stack overflow，
但**建议白天正常聊几句（容易出现惊讶语气）再确认一次**。

如果 16384 还崩，下一步两条路：
1. 继续加栈（24576）——简单，但吃内部 RAM（当前 free sram 约 80KB）
2. 改 `ExecuteSurpriseAnimation()`，别用 `lv_refr_now(NULL)` 同步全树刷新，
   改成 `lv_obj_invalidate()` 交给 LVGL 自己的定时器刷 —— 治本，但要调动画手感

## 7. 顺带确立的排查手法

| 想确认什么 | 怎么做 |
|---|---|
| 设备是断线还是重启 | 对比"设备上线"次数 vs "OTA请求设备ID"次数；再看有没有"客户端断开连接" |
| 设备有没有真出声 | 看 LAST 之后设备有没有发 `{"type":"listen","state":"start"}`（详见 `docs/35`） |
| 跑的是不是新固件 | 串口 `ELF file SHA256` 前 9 位 vs 本地 `sha256(build/xiaozhi.elf)`，**别信 Compile time** |
