## 2. 小度音箱是怎么做到"绑定酷狗点歌"的？为什么个人做不到

小度（DuerOS）绑定酷狗后能点歌，本质是 **B2B 内容授权 + 厂商私有云 API**：

- 百度与酷狗（腾讯音乐）做**商务合作**，拿到的是**内容授权接口**（搜索/播放地址/鉴权走的是服务端 token）。
- 小度音箱自己不装酷狗，它是把"放某首歌"的意图发给酷狗/腾讯的**云接口**，拿到音频流 URL 再播。
- 这套东西：① 不开源；② 需要企业资质签约；③ 个人开发者无入口。

> 所以"小度怎么做的"这条线**只能当知识了解，不能当实现路径**。你手上真正能用的，是"在自己电脑上自动化那个酷狗客户端"。

## 3. 三条技术路线详解

### 3.1 传输控制（播放/暂停/上一首/下一首）—— 两条稳路

**路线 ①：SMTC（Windows 系统媒体传输控件）— 首选**

Win10/11 上，酷狗会把自己注册成一个 **媒体会话（Media Session）**（就是任务栏/音量键弹出来的那个控制条）。

- Python 侧用 `winsdk` / `winrt` 调 `GlobalSystemMediaTransportControlsSessionManager`：
  - **读**：当前曲目标题、艺术家、专辑、播放状态 → 可以拿来做"正在播放 XXX"的语音播报
  - **写**：`TryPlayAsync / TryPauseAsync / TrySkipNextAsync / TrySkipPreviousAsync`
- **优点**：不抢焦点、不模拟按键、不会误触别的软件，最干净。
- **缺点**：需要酷狗正确实现 SMTC（酷狗实际支持，任务栏媒体条就是证据）；需要装 `winsdk` 到托管 venv。

**路线 ②：全局热键（备用）**

酷狗自带全局快捷键（播放/暂停、上一首、下一首），用 `SendInput` 发组合键即可。

- 具体绑定可在"酷狗 → 设置 → 快捷键"里看到并自定义，建议**先抄下来做映射表**。
- **缺点**：会抢焦点，可能和别的软件冲突。作为兜底方案。

### 3.2 点播指定歌曲（"给我放首《XXX》"）—— 分级方案

**Plan A（首选）：CEF 远程调试（CDP）**

因为酷狗是 CEF，理论上可以：
```
KuGou.exe --remote-debugging-port=9222
```
启动后 `http://127.0.0.1:9222/json` 若列出页面目标，就能用 **Chrome DevTools Protocol** 直接操作内嵌网页 DOM：往搜索框填歌名 → 点第一首结果 → 点播放。

- **优点**：走的是网页结构，不依赖皮肤/分辨率，最稳、最可维护。
- **前提**：需要 **30 分钟 PoC 验证这个参数是否被酷狗接受**（CEF 应用有的屏蔽、有的放行）。这是整个方案里**唯一的未知数**，必须实测。

**Plan B（备选）：UI Automation**

用 `pywinauto` / FlaUI 抓 Chromium 的无障碍树，定位"搜索框""歌曲列表项""播放按钮"。

- CEF 的 a11y 树比传统自绘 UI 完整得多，可行性不低。
- **缺点**：按控件名字/层级找元素，酷狗大版本改版就可能失效。

**Plan C（下策，不推荐）：键鼠模拟**

点击搜索框坐标 → 键入 → 回车。最脆，分辨率/窗口位置一变就废。

### 3.3 另一条"绕开酷狗 UI"的路（要权衡）

既然真正要的是"电脑出声 + 指定歌曲"，其实**不必死磕酷狗客户端**：

| 选择 | 曲库/音质 | 稳定性 | 说明 |
|---|---|---|---|
| 自动化酷狗客户端 | ✅ 你的 SVIP 曲库/音质 | 中 | 本文主张，吃 SVIP 红利 |
| 第三方音乐 API + 本地播放器（MPV/VLC/foobar） | ❌ 用不上酷狗 SVIP | 高 | 稳定，但曲库和音质另说 |

> **权衡点交给用户**：要酷狗曲库/SVIP 音质 → 就得自动化它的界面（接受脆弱性）；要绝对稳定 → 换播放后端。

## 4. 与小智项目的对接架构

这正是 `pc_run_task` 投递箱的自然延伸，**不需要重编固件**：

```
小智(语音) → 后台(DeepSeek 意图解析)
                ↓ 意图=music，槽位=歌名/动作
        music skill → PC 常驻 helper: pc_music.py
                          ├─ 传输控制 → SMTC / 全局热键
                          └─ 点播       → CDP / UIA 在酷狗里搜+播
                ↓ 读 SMTC 当前曲目
        8004 主动播报 → 小智回念"好的，给你放《XXX》"
```

**关键纪律（沿用本项目教训）：** helper 必须是 **常驻进程**，由管理台托管拉起，**不能依赖 AI 会话进程**（会话结束会被沙箱整棵回收）。

## 5. 风险与坑

1. **版本改版**：酷狗大版本升级会改内部结构 → CDP 走 DOM 相对抗跌，UIA 次之，键鼠模拟最先死。定位逻辑要写成**可配置**的。
2. **焦点偷取**：CDP / UIA 不抢焦点；键鼠模拟会抢。优先前者。
3. **合规边界**：驱动自己的客户端 + 自己的账号播放自己有权听的内容，属**个人本机自动化**，灰色但不涉破解；不传播、不绕过付费即可。
4. **依赖**：SMTC 需装 `winsdk`（WinRT 绑定）到托管 venv。
5. **后台静默**：helper 静默自启要参考管理台那套（无控制台窗口 + 开机自启项）。

## 8. PoC-1 实测结果（2026-10-02 19:05，已执行）

**结论：CDP 路线 ❌ 关闭 → 点歌改走 UI Automation。**

| 试验 | 启动方式 | 结果 |
|---|---|---|
| A | 版本目录 exe `20.1.51.27967\KuGou.exe --remote-debugging-port=9222` | **进程根本没起来**（tasklist 空）→ 该 exe 不能独立启动，必须走根启动器 |
| B | 根启动器 `KGMusic\KuGou.exe --remote-debugging-port=9222` | 正常起 6 个进程（主+渲染器），但 **9222 无监听** |
| C | 版本目录 exe + `--remote-allow-origins=*` | 同 A，未起 |

**旁证（判定"它读不读命令行参数"）**
- 追加 `--enable-logging --v=1` 后，`20.1.51.27967\debug.log` 出现本次运行的条目（时间戳 `1002/190755`、`1002/190909`）。
- 同时抓了它自开的端口：`0.0.0.0:8020`、若干 127.0.0.1 高位口；8020 **不是 HTTP**（TCP 通但 HTTP 超时）。
- → **CEF 确实处理了启动，但调试端口被代码里写死（`CefSettings.remote_debugging_port` 覆盖了命令行开关）**，命令行这条路走不通。

**踩到的环境坑（两个，都会骗你）**
1. **本机有 HTTP 代理（127.0.0.1:10808/10809）**，`urllib` 会把 `127.0.0.1:9222` 也送进代理 → 返回 **502 Bad Gateway**，看着像"端口活着"。必须 `ProxyHandler({})` 绕过，否则误判。
2. **PowerShell 被沙箱禁止启动 exe**（报 "Starting cmd.exe from PowerShell bypasses PowerShell command validation"）；**脱离 AI 回合启动的进程会在回合结束时被回收**（实测第二次探测时进程已消失）。→ 启动+探测必须写在**同一次脚本执行**里。

**可复用工具**（已落盘）
- `tools/poc_kugou_cdp.py` —— 启动并探测 CDP（含代理绕过 + 裸 socket 双判据）
- `tools/poc_kugou_diag.py` —— 三种启动方式对照诊断
- `tools/poc_kugou_cdp2.py` —— 命令行参数生效性判定
- `tools/poc_kugou_ports.py` —— 本地端口扫描（找出代理端口，避免误判）
