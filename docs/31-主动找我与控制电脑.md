## 2. 任务完成别再念一长串数字（P0）

根因在 `plugins_func/functions/pc_control.py::pc_run_task`：
返回给 LLM 的指令里带了 `编号 {tid}`（形如 `20261003-010512`），模型就照念。

修法：**编号不再进对话**，只落盘到任务单（查询时可用）。新指令：

```
任务已成功交给电脑上的助理，任务内容是「…」。
请用一句自然口语告诉主人这就去办。
严格要求：1）不念任何编号/数字串/时间戳 2）不复述任务原文
3）不说已完成（等回执） 4）一句话二十字以内
```

## 5. 完全控制电脑：补到桌面层（P1）

新增 **`core/pc_desktop.py`**（纯 ctypes，零第三方依赖），
`pc_agent` 工具数 **11 → 16**：

| 工具 | 能力 |
|---|---|
| `list_windows` | 列出打开的窗口（标题 + 是否最小化） |
| `window_action` | 置前 / 最小化 / 最大化 / 还原 / 关闭（模糊匹配标题） |
| `clipboard` | 读 / 写系统剪贴板 |
| `send_keys` | 组合键 `ctrl+c`/`alt+tab`/`win+d`，或打字 |
| `screenshot` | 全屏或指定窗口截 PNG（手写 PNG，不依赖 Pillow） |

**踩坑记录（值得记住）**：64 位 Python 上调 Win32，
**凡返回句柄的函数必须显式声明 `restype`/`argtypes`**，否则指针被截成 32 位 int：

- 不声明 → `GlobalLock` 拿到 0x0 → `access violation writing 0x0000000000000000`
- 不声明 → `SetClipboardData` / `ReleaseDC` → `OverflowError: int too long to convert`

另外 `SetProcessDPIAware()` 不加的话，1920×1080 会被报成 1280×720。

## 7. 舵机供电（主人第三问的答复）

**不用一直插数据线。** 数据线（USB-C）只在这两种情况下需要：

1. 刷固件
2. 抓串口日志排障

日常使用：设备靠**电池供电 + Wi-Fi 连后台**就够了，语音、播报、派活全走 Wi-Fi，
跟电脑之间没有物理连线依赖。

**为什么 USB 供电时舵机不动**：不是代码分支（同一份固件不可能有两种行为），
是**电流**。ESP32 本体 5V/500mA 够，但两个 MG90S 舵机堵转可达 1A，
电脑 USB 口限流后 5V 塌陷，舵机就没劲/不抖/不动。
主人实测"电池 + 插线同时供电时正常" —— 正好坐实这点。

**建议**：日常就用电池；若必须长期插电，舵机 5V 独立供电（**必须共地**）。
