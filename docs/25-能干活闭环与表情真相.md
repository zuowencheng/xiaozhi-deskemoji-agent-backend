## 1. ① 能干活闭环：三段全通

链路设计（不重编固件，全部在后台侧）：

```
小智(语音) → 后台LLM 判断"要在电脑上动手"
            ↓ 调 pc_run_task
       写 bridge/inbox/task-<id>.md        ← 【新增】plugins_func/functions/pc_control.py
            ↓ 执行者（WorkBuddy）干活，写 done/
       常驻 watcher 扫 done/               ← 【新增】core/notify_plugin.py
            ↓ 有结果
       8004 → 设备 TTS 主动开口             ← 复用已有插件
            ↓
       写 announced/<id>.mark（防重复念）
```

### 1.1 新增服务端插件 `plugins_func/functions/pc_control.py`
- 注册两个工具：**`pc_run_task`**（派活）/ **`pc_query_task`**（问进度）
- 任务文件格式与 `bridge/server_agent.py::_task_body()` **逐字一致**（契约见 `docs/03`）
- 投递箱路径由 `__file__` 反推项目根，可用环境变量 `XZ_BRIDGE_DIR` 覆盖
- 同秒撞号自动加后缀，**绝不覆盖**已有任务

### 1.2 新增服务端插件 `plugins_func/functions/reminder.py`
- 注册三个工具：`set_reminder` / `list_reminders` / `cancel_reminder`
- 复现 `core/notify_plugin` 的存储与时间解析，不重复造轮子

### 1.3 `core/notify_plugin.py` 升级（一个文件干三件事）
| 新增能力 | 说明 |
|---|---|
| **取件 watcher** | 每 5s 扫 `bridge/done/`，未播报的完成结果 → 主动开口 → **发送成功才写标记**（设备不在就下轮重试，不吞结果） |
| **定时提醒循环** | 每 15s 检查 `data/reminders.json`；一次性到点即报并置 `enabled=false`，`daily` 的顺延到明天 |
| **HTTP 扩展** | `POST /remind`、`GET /remind/list`、`POST /remind/delete` |

> ⚠️ 两个循环都**在自建后台进程里**，不另起进程——因为后台是常驻服务，而 AI 会话拉起的进程会被回收（本项目已踩两次）。

### 1.4 配置改动
- `data/.config.yaml`：`Intent.function_call.functions` **新增 `pc_control`、`reminder`**
  - ⚠️ 关键坑：`merge_configs` 递归合并，但 **`functions` 是列表 → 列表整体覆盖**，
    所以必须把 `config.yaml` 原有的项（change_role/web_search/get_weather/get_news_from_newsnow/play_music）也列全，否则被顶掉。
  - 模块名会被 `module_func_map` 自动展开成具体函数名。
- `agent-base-prompt.txt`：新增 `<pc_control_rule>`，明确"**不要自己编结果**，必须调 pc_run_task；
  绝对禁止没调工具就说'已经做好了'"（沿用 17:00 那条教训：工具没被调用，先怀疑提示词）。

### 1.5 执行者（闭环里唯一"人工"环节）

## 2. ② "表情不动"的真相：不是 bug，是**模式**（重要认知修正）

### 2.1 实情
| 事实 | 证据 |
|---|---|
| `emoji_screen_` 只在 `CreateEmojiScreen()` 里创建 | `emoji_controller.cc:266` |
| `CreateEmojiScreen()` **只在 `SwitchScreen(true)` 里被调用** | `emoji_board.cc:283`（函数体已被 SwitchScreen 取代） |
| `SwitchScreen(true)` **只在长按 BOOT 进"表情模式"时触发** | `emoji_board.cc:214-235` |
| `is_emoji_mode_` 初值 **false** | `emoji_board.cc:107` |

→ **开机默认是"对话模式"（文字屏），表情屏根本不存在**，
于是所有表情动画在 `emoji_screen_ == nullptr` 处被静默 return，串口刷
`ExecuteRandomAnimation: 屏幕或眼睛对象不存在`。

**所以正确的操作是：长按 BOOT 键进"表情模式"。** 这不是坏，是设计。

### 2.2 已做的改进：**自动表情**（`emoji_board.cc`）
新增 `EmojiBoard::FlashEmoji()`：AI 触发情绪时，**对话模式下自动把表情屏亮出来，静默 5 秒后自动切回文字屏**。
- 中性表情不切屏（避免无谓闪烁）
- 手动表情模式下不打扰（`is_emoji_mode_` 直接 return）
- 连续情绪只重置计时器，不反复切屏
- 长按退出表情模式时同步复位自动表情状态（否则表情屏被删后会"只创建不显示"）
- 定时器回调**不套 DisplayLockGuard**（回调本就在 LVGL 任务里跑，已持锁）

锁确认：`OledDisplay::Lock` → `lvgl_port_lock`（**递归锁**），嵌套取锁安全。

### 2.3 仍然存在的噪声（暂不处理）
固件自带 **idle 动画循环**：每 5~10 秒发一次随机动画（类型 27）、眨眼动画（类型 0）。
在对话模式下这些仍会打 `屏幕或眼睛对象不存在` 警告（无害，只是刷日志）。

**如果你想要"表情常驻"的桌宠形态**，有个一行改法（把开机默认设成表情模式），
但那会让文字状态（聆听中/说话中）默认不可见——**这是个取舍，等你拍板**。

## 3. ③ 定时提醒：语音可设，到点自己开口

- 语音："小智，明天早上八点提醒我交房租" → `set_reminder` → 落盘 → 到点主动播报
- 直接调 API 也行：`POST http://127.0.0.1:8004/remind {"text":"...","at":"08:00","daily":true}`
- 时间格式：一次性用 `YYYY-MM-DDTHH:MM`；每天重复用 `HH:MM` + `daily:true`
- 存储：`server/xiaozhi-server/data/reminders.json`

## 5. 需要你做的事（设备侧验证）

1. **启动后台**：双击 `server/admin/start_admin.cmd`（会顺带拉起后台 + 管理台 8005）。
   > 服务不要由我来起——AI 会话拉起的进程会在回合结束时被回收。
2. **唤醒设备**（说"你好小智"或按一下 BOOT 短按），让它连上 WS。
   连上后 `GET http://127.0.0.1:8004/notify/status` 的 `online` 就不再是空数组。
3. **验证能干活**：对小智说「帮我在电脑上查一下明天北京的天气，写成一个 txt 放到桌面」，
   看它是否回"这就去办"；然后看 `bridge/inbox/` 是否出现任务单。
4. **验证表情**：跟它聊几句带情绪的话（逗它笑），看屏幕是否**自动切到表情脸、5 秒后回到文字屏**。
5. **验证提醒**：说「三十秒后提醒我喝水」，等 30 秒听它主动开口。

## 6. 已知缺口与风险

| 项 | 说明 |
|---|---|
| **执行者时延** | 投递箱要靠 automation 取件，现在是**每小时**一次。想让"说一句就办"接近实时，需要挂常驻 watcher 或缩短周期（成本是每次跑一个完整 AI 回合）。**这是目前最大的体验缺口。** |
| idle 动画日志噪声 | 对话模式下仍刷 `屏幕或眼睛对象不存在`（无害） |
