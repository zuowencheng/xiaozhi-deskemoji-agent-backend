# 61 · 开机自启 + 服务自愈（看门狗）

> 起因：2026-10-04 用户重启电脑后，小智后台**一个都没起来** ——
> 8000/8003/8004/8005 四个端口全 closed，`tasklist` 里没有任何 python 进程。

## 一、为什么重启后没起来

**根因：开机自启从来就没装上过。**

原设计是「启动文件夹放一个 VBS」：

```
autostart_on.cmd  ──copy──▶  %APPDATA%\...\Startup\XiaozhiAdmin.vbs
                                    └─▶ python admin_server.py 8005 --autostart
                                              └─▶ 再拉起 app.py (8000/8003/8004)
```

但实测启动文件夹里**只有 `desktop.ini`**，压根没有那个 VBS ——
`autostart_on.cmd` 需要**手动双击**才会安装，而它从没被执行过。

> 教训：**"写了安装脚本" ≠ "装上了"**。任何自启都要能验证落地状态
> （`install_autostart.py --status` 就是干这个的）。

### 顺带发现的两个设计缺陷

1. `admin_server.py: main()` 里 `if port_alive(port): return` 排在 `--autostart` 分支**之前** ——
   如果 8005 被别的方式占用（比如手动双击 `start_admin.cmd` 不带 `--autostart`），
   开机时 VBS 起的 admin 会发现端口占用**直接 return，不再去拉起 8000**。
2. 旧 VBS 的 `sh.Run` 那行路径**没加引号**（靠"路径不含空格"侥幸）。
   一旦项目目录改名带上空格，就会解析失败。

## 二、现在的机制（两层）

```
Windows 登录
   │  (延迟 15s)
   ▼
启动文件夹\XiaozhiSvcWatchdog.vbs      ← 静默、无窗口
   │  pythonw 启动
   ▼
tools/svc_watchdog.py                  ← 常驻，每 20s 巡检一次
   │  端口不通 → 拉起
   ├─▶ app.py         (8000 WS / 8003 OTA+视觉 / 8004 主动播报)
   └─▶ admin_server.py(8005 管理台)
```

**职责分离**：VBS 只管"登录时把看门狗叫起来"，看门狗只管"谁挂了我补谁"。
两件事各自简单，互不耦合。

### 看门狗参数（`tools/svc_watchdog.py` 顶部）

| 常量 | 值 | 说明 |
|---|---|---|
| `CHECK_INTERVAL` | 20s | 巡检间隔 |
| `RETRY_CONFIRM` | 2 | 连续 2 次探测失败才认定挂了，防抖动误判 |
| `GRACE` | 40s | 拉起后冷却期，避免端口 TIME_WAIT 期间的重复拉起 |
| 单实例 | 命名互斥体 `XiaozhiSvcWatchdogMutex` | 重复启动直接退出，防两个看门狗互抢 |
| 日志 | `server/_logs/watchdog.log` | 超 2MB 自动轮转 |

只检查 **8000** 和 **8005** 两个端口：8003/8004 与 8000 同属 app.py 进程，
8000 活着它们就都在。

→ **服务级自愈闭环成立**。

## 四、怎么开关 / 查看

```bat
:: 装（会产生启动文件夹里的 VBS）
python tools\install_autostart.py --install

:: 查
python tools\install_autostart.py --status

:: 立刻启动看门狗（不重启也能起，借 explorer 脱离会话）
python tools\install_autostart.py --run

:: 卸
python tools\install_autostart.py --uninstall
```

也保留了双击入口：`server\admin\autostart_on.cmd` / `autostart_off.cmd`。

## 五、两条已知边界（暂不覆盖）

1. **进程"半死"（hang）但端口还开着** → 看门狗检测不到，不会重启。
   要覆盖得加 HTTP 健康检查（对 8005 打一个探针接口 + 超时判定），
   但那会引入误判风险，暂不做。
2. **8003/8004 单独挂**（app.py 只崩了一条监听线程）→ 同上，只看 8000 存活。

## 六、沙箱限制备忘

- `schtasks /create` 在本机沙箱里**被拒绝访问**（改系统任务被拦），
  所以默认走 `--method vbs`（纯文件操作，免管理员）。
- 想要"失败自动重启 + 不因电池停止"这类高级选项时，用
  `python tools\install_autostart.py --install --method task`，
  **在管理员 cmd 里跑**（XML 里已配好 `RestartOnFailure` / 电池条件 / 无时长限制）。
