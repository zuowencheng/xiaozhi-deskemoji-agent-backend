# 24 · 让小智从"会说话的玩具"变成"真正的助理" —— 价值路线图

> 日期：2026-10-02
> 前提：语音链路已通（自建后台 + DeepSeek）、设备已刷自研固件、投递箱骨架已通、主动播报口（8004）已就位。
> 本文回答两件事：**① 怎么让它在你日常/工作里真正有用；② 这玩意儿能不能拿去卖。**

---

## 0. 先给结论（三句话）

1. **它的价值不在硬件，在"它接谁"。** ESP32-S3 算不动任何东西，它的真正身份是一个**免手、常开、有在场感的语音终端**——大脑必须放在 PC/云上。别在硬件上找价值（加摄像头、加传感器都是弯路，`docs/14` 已评估过）。
2. **"音箱 → 助理"只有一条分水岭：主动。** 你问它答 = 音箱；**它主动开口 = 助理**。所以当前最高优先级不是加功能，是把**主动播报 + 定时任务**这条线做扎实。
3. **要卖，卖的不是板子，是"开箱即用的助理系统 + 记忆 + 服务"。** 硬件没有壁垒。

---

## 1. 三个分水岭：怎么判断它"像不像助理"

| 分水岭 | 音箱 | 助理 | 本项目现状 |
|---|---|---|---|
| **主动性** | 你问才答 | 它主动找你（提醒/汇报/预警） | ⚠️ 接口有了（8004），**闭环没跑通** |
| **记忆** | 每次从零开始 | 记得你是谁、上次干了啥、你的偏好 | ⚠️ 设计定稿（`docs/04`），**未接入** |
| **闭环** | 回一句废话 | 你一句话 → 它办成 → 回来告诉你结果 | ⚠️ 骨架通，**LLM 未接上** |

**三个都是"半成品"。把它们各自补完 80%，比再加十个新功能都有用。**

---

## 2. 能力分层：按"投入产出比"排序，不按"酷不酷"

### 🟥 第一层 · 让它能干活（P0，最高优先）
> 目标：**你说一句话，它真的把事办成，并且回来告诉你。**

| 项 | 内容 | 现状 |
|---|---|---|
| 1.1 | 把 `pc_run_task` / `pc_query_task` 接进 LLM 工具表 | 工具在，**没注册** |
| 1.2 | 常驻 watcher 取件（**不能**让 AI 会话取，会被回收） | 未做 |
| 1.3 | 干完 → 8004 主动播报 → 它开口说"弄好了" | 接口就绪，**未串联** |
| 1.4 | 设备常连（`close_connection_no_voice_time` 120→86400） | 配置已改，**待验证持久性** |

**做完这层的效果：** 你说"帮我把桌面上那个表格整理一下"，它派任务 → WorkBuddy 干活 → 干完它主动开口："表格整理好了，放在桌面了。" —— **这才是助理。**

### 🟧 第二层 · 让它有"存在感"（P1）
> 目标：它"活着"，不是一个会说话的盒子。**这一层是情绪价值，也是产品差异化的关键。**

| 项 | 内容 | 现状 |
|---|---|---|
| 2.1 | **修表情图层 bug**（`ExecuteRandomAnimation: 屏幕或眼睛对象不存在`） | ❌ 表情完全不动，**硬伤** |
| 2.2 | 舵机做"情绪动作"：唤醒点头、思考歪头、完成转身、拒绝摇头 | ❌ 未做 |
| 2.3 | 屏幕状态机：待机 / 聆听 / 思考 / 播放 / 错误（不同表情+动效） | ⚠️ 部分有 |
| 2.4 | 唤醒/结束的"应答语气"统一（现在偏机械） | ⚠️ 待打磨 |

**为什么这层重要：** 桌宠的价值一半在"像个活物"。它不动，用户三天就腻；它会点头会歪头，用户会一直留着它。**对将来卖产品，这是最便宜的差异化。**

### 🟨 第三层 · 让它真的"有用"（P2，场景清单）
> 按**使用频率**和**实现成本**挑，不要全做。建议先做前 3 个。

| 场景 | 用户说什么 | 实现要点 | 频率 | 成本 |
|---|---|---|---|---|
| **⏰ 定时主动提醒** | （不需要说，它自己开口） | automation 定时 + 8004 播报。日程提醒、待办、久坐/喝水 | 极高 | 低 |
| **📝 口述记录** | "小智，记一下：明天要交房租" | ASR 文本 → 落盘 markdown / 投递箱 → 主动确认 | 高 | 低 |
| **🖥️ 电脑操控** | "把浏览器打开" / "放首歌" / "锁屏" | 投递箱派任务给本机（**已有**）+ 音乐控制（`docs/23`） | 高 | 中 |
| **🧠 记忆问答** | "我上次让你干啥了？" | 接 `bridge/memory.py`（bge-m3 已就绪） | 高 | 中 |
| **📅 晨间简报** | "早上好" / 定时自动 | 天气 + 日程 + 待办 + 新闻摘要，合成一段说给你听 | 中 | 中 |
| **📚 知识库问答** | "我那个项目文档里怎么写的" | RAG 接个人知识库（`docs/13` 已预留接口） | 中 | 高 |
| **🤖 任务委派** | "帮我把这个需求实现一下" | 投递箱 → Codex/WorkBuddy 长任务 → 完成播报 | 中 | 中 |
| **🍅 番茄钟/专注** | "开始专注" | 定时 + 语音陪伴 + 结束提醒 | 中 | 低 |
| **💡 家电控制** | "把台灯打开" | 官方 board 自带 `LAMP_GPIO` MCP，配你清单里的继电器 | 低 | 低 |

### 🟩 第四层 · 多端统一（P3）
手机 App / WROOM-32 紧凑版 / 未来树莓派大脑——**连同一后台 → 记忆统一**（`docs/12` 已评估：旧手机不能刷机，但能当客户端）。
价值：走到哪都是"同一个助理"，不是三个各记各的。

## 3. 商业化：说点实在的，不画饼

### 3.1 先认清一件事
**硬件本身没有壁垒。** ESP32-S3 + 开源小智固件，任何人花 ¥60~150 就能复刻，卖板子你拼不过华强北。
**真正能卖的只有三样：**

| 壁垒 | 说明 | 能不能守住 |
|---|---|---|
| **软件栈** | 开箱即用、不用用户动手的成品系统（现在这套要配环境、刷固件，普通人做不到） | ✅ 强 |
| **记忆数据** | 用得越久越懂你，**换走成本极高**（这是最强的护城河，也是最敏感的数据） | ✅ 极强 |
| **服务** | 云端大脑、技能库持续更新、售后、行业定制 | ✅ 中 |

### 3.2 商业模式（由轻到重）
1. **硬件微利引流 + 订阅**：机器 ¥199~399（覆盖成本），订阅 ¥15~30/月（云大脑 + 记忆 + 技能库更新）。
   —— 对标：小度/天猫精灵是硬件亏本 + 内容/服务回本，个体创业者只能走"小批量 + 订阅"。
2. **行业定制**：办公室行政助理、创客教育套件（带课程）、老人看护提醒。
3. **开源+赞助 / 卖"整套方案"**：开源固件，卖"一键部署包 + 云服务"。

### 3.3 谁会买
- **不想动手但想要的人**：办公室白领、独立开发者、学生、家里有 NAS/软路由的人。
- **不会买的人**：只要音箱功能的（买个天猫精灵 ¥99 就行）；纯极客（自己会搭，不会付费）。

### 3.4 ⚠️ 先决条件（最重要的一条）
> **你自己得先天天用它，用到"离开它会不习惯"，才谈得上卖。**
> 一个连你自己都不用的产品，卖给谁都是自欺欺人。

**所以顺序是死的：**
```
闭环跑通 → 自己天天用（吃狗粮）→ 提炼出 1~2 个"杀手场景" → 再谈产品化
```
**现在谈卖还太早。先把第 0 章的三个分水岭补完。**

### 3.5 风险（必须提前想清楚）
| 风险 | 说明 |
|---|---|
| **合规** | 语音内容审核、数据出境、未成年人保护；国内做语音类产品要过审 |
| **隐私** | 你现在的优势是"声音不出网"，一旦上云卖服务，这条优势就没了——用户会问"我的录音去哪了" |
| **硬件售后** | 退货率、维修、物流，硬件生意最烦的就是这个 |
| **云成本** | 订阅制下，大模型调用 + TTS 成本是浮动的，量大了可能倒亏 |
| **巨头下场** | 小米/百度/字节随时可能把同类功能做进 ¥199 的音箱 |

## 5. 一句话总结

> **别想着给它加新本事，先把它已有的三样本事补完：让它能干活、会主动开口、记得住你。**
> **这三样补完，它就从"玩具"变成"助理"了；到那时候，你自己就会知道该不该卖、该卖给谁。**
