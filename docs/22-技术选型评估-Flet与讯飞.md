# 技术选型评估：管理台用 Flet？对话接讯飞 AIUI？

> 评估日期：2026-10-02
> 结论先行：**Flet 不建议换（现方案更优）；AIUI 不建议接（定位错配 + 破坏隐私边界）；但讯飞星火大模型值得作为 LLM 备选接入（零改动）。**

---

## 一、管理台换 Flet？

### Flet 是什么

Flet = **用 Python 写 Flutter**。底层把 Flutter 当渲染引擎，你用 Python 描述 UI，它跑一个服务端进程 + 前端渲染层，同一套代码可跑桌面 / Web / 移动。

### 对"管理台"这个场景的账

| 维度 | Flet | 现状（纯标准库单文件 HTML） |
|---|---|---|
| 依赖 | `pip install flet`，带 Flutter runtime | **零依赖**，Python 自带 http.server |
| 打包体积 | PyInstaller 打出来 **100~300MB** | 脚本本身 **~40KB** |
| 启动 | 要拉起渲染层，秒级 | **毫秒级** |
| 常驻方式 | 桌面模式=有窗口（不适合无头自启）；Web 模式=要跑 Flet server | 直接跑 HTTP server，**适合静默自启** |
| 首屏 | Web 模式要下载 Flutter Web 渲染引擎（wasm，MB 级） | 一个 HTML 字符串，**即时** |
| 生态 | 组件比成熟 Web 少，版本迭代快（有过 breaking change） | 想加什么直接写 HTML/CSS |
| 调试 | 不如浏览器 DevTools 直观 | **F12 直接调** |
| 好看程度 | **胜** | 朴素 |

### 判断

**现阶段不建议换。** 三条理由：

1. **它是给"产品"用的，不是给"自己一个人的工具"用的。** 管理台是给你一个人看的，可靠性和随手可改 > 视觉精美。
2. **跟"开机静默常驻"这个刚需冲突。** Flet 桌面版是窗口程序，无头自启不合适；Web 版能跑但比一个 HTTP server 重得多。
3. **为一个管理台引入几百 MB 运行时 + 一个新依赖，性价比倒挂。** 现在的零依赖方案，上游源码改了你照样能跑。

### 如果确实想升级，更贴的路子是这两条

| 方案 | 适合 | 特点 |
|---|---|---|
| **NiceGUI** | 想"好看点 + 不碰 JS" | Python 写，但**输出真 HTML/Vue**（FastAPI 底座），比 Flet 轻、更 Web 原生 |
| **FastAPI + Vue/React** | 目标是"产品级管理后台" | 主流、生态全、可扩展，代价是要写前端 |

> 一句话：**要轻 → 保持现状；要好看又不想碰 JS → NiceGUI；要做产品 → FastAPI + 前端框架。Flet 卡在中间，不上不下。**

## 二、对话接讯飞 AIUI？

### 先掰概念：AIUI ≠ 对话大模型

这里有三个东西容易被当成一个，必须分开：

| 名称 | 是什么 | 定位 |
|---|---|---|
| **AIUI** | 人机交互**平台**（语音唤醒 + 识别 + 语义 + 合成打包） | **面向智能硬件厂商**，多语种出海方案 |
| **星火大模型** | 真正的对话**大脑**（LLM） | 面向开发者，API 兼容 OpenAI |
| **开放平台单项能力** | 语音听写 / 语音合成 / 唤醒 等，按能力单独买 | 面向开发者，按量/按套餐 |

**你说的"AI 对话接 AIUI"——AIUI 里没有你要的那种"对话大模型"，它是个语音交互底座。** 真正要接的对话大脑是**星火**。

### AIUI 的效果与费用

- **效果**：讯飞语音能力国内第一梯队，官方披露英语识别率 97.35%、端到端场景准确率 95.12%，覆盖 40+ 语种。这个没什么可挑的。
- **费用**：AIUI 主打 **"按台付费"**（面向出厂设备的硬件厂商），提供**免费测试用量**，商用需授权。**它是企业级商用平台，个人开发者拿不到对个人的免费套餐。**

### 开放平台单项能力的价格（供参考）

> ⚠️ 以下为公示价，政策会变，**实际以控制台为准**。

| 能力 | 套餐 | 价格 |
|---|---|---|
| 语音听写 | 20 万次/年 | 1000 元 |
| 语音听写 | 100 万次/年 | 4000 元 |
| 在线语音合成 | 100 万次/年 | 5800 元 |
| 免费额度 | 合成 SDK+Web | **每天 500 次** |
| 免费额度 | 企业实名认证 | 领"乐享会员试用版"，可任选 3 项（含听写 5 万次/年）|

### 星火大模型（这才是能接的"对话"）

| 项 | 值 |
|---|---|
| Spark Lite | **完全免费** |
| 新用户 | 送 **200 万 tokens** |
| Spark 4.0 Ultra | 免费使用（fair use 限额） |
| API 协议 | **兼容 OpenAI**（`base_url = https://spark-api-open.xf-yun.com/v1`） |

### 判断：不建议接 AIUI

三条理由：

1. **定位错配**：AIUI 是硬件厂商的商用平台，个人自用场景用不上它的核心价值（多语种、按台付费、全球部署）。
2. **破坏你的隐私边界**：现在架构是**本地 ASR（Sherpa）→ 声音不出网**。接 AIUI = 把声音送出去，**直接违反你定的 P1 红线**。
3. **能力重叠**：ASR 和 TTS 我们已经有了（本地 + EdgeTTS 免费），AIUI 替换这两块是**负收益**（变慢、变贵、丢隐私）。

### 真正值得做的：星火大模型作为 LLM 备选

**因为星火兼容 OpenAI 协议，而我们的服务端用的就是 `openai` provider —— 接入约等于改 3 行配置。** 可以拿它当 DeepSeek 的**备份/对比/兜底**（有免费额度）。

## 三、结论汇总

| 问题 | 结论 |
|---|---|
| 管理台换 Flet？ | ❌ 不建议。要升级走 NiceGUI 或 FastAPI+前端 |
| 对话接 AIUI？ | ❌ 不建议。定位错配 + 破坏隐私边界 + 能力重叠 |
| 星火大模型？ | 🟡 可选。兼容 OpenAI，零改动可接，建议当 DeepSeek 备选 |
| 云端语音（听写/合成）？ | 🟡 仅当你愿意把声音送出网时才考虑，否则维持本地 ASR |
