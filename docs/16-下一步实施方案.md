板子上现在这版（社区 fork，含 PAJ7620 手势 + 音乐 + 表情）**功能和引脚都是好的、已验证能跑**。Stage A 只改一个 URL，改动面最小、成功概率最高。

- ✅ 回滚包已在 `hardware/reports/rollback_kit/`（`ota_0_app.bin` / `otadata.bin` / `nvs.bin` / `rollback_app.cmd`）

**1. 克隆 + 自动识别 + 编译**（一条命令）

```powershell

  "C:\Users\zuowe\WorkBuddy\2026-10-02-01-36-40\xiaozhi-deskemoji-agent\tools\stage_a_build.py"
```

这个脚本干四件事（每步都打印，失败即停）：

> - 或者接受差异，但**编完后要连 `assets` 一起刷**（`esptool write-flash 0x900000 build/assets.bin`）

**2. 写进 ota_1（不碰 ota_0）**


`otadata` 是 8KB 的"启动选择器"（偏移 0xd000），切它不动任何固件内容，所以这是**可逆的**。

> 额外保险：这份 `sdkconfig.defaults` 里有 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`，
> 也就是说固件启动后若没能"确认有效"，bootloader 有机会自动回滚。等于多一道自动保险。

### 可选快捷路径（先花 5 分钟探一下）

板载固件里 `https://api.tenclass.net/xiaozhi/ota/` 是**普通字符串常量**（38 字符），而 `http://192.168.3.139:8003/xiaozhi/ota/` 只有 **36 字符**——**比它还短**。理论上可以从 16MB 备份里把 ota_0 那段（0x100000 起 4MB）抠出来，**原地改字符串**，写进 ota_1 —— **完全不用编译**。

**风险**：ESP32 app 镜像尾部带 SHA256，bootloader 可能校验；不过这份 fork 的配置里有 `CONFIG_BOOTLOADER_SKIP_VALIDATE_ALWAYS=y`（跳过校验），有机会成立。因为只写 ota_1，**失败了切回 ota_0 就好，是零风险试探**。

**要不要试**：我可以写一个**只读扫描脚本**，先在备份里确认这个字符串真的以明文存在、以及有几个候选（怕改到别处）。你说一声我就写——**这一步是纯信息，不改任何东西**。

## 四、线 2 · 主动播报接口（代码已落地）

### 实现方式

| 文件 | 作用 |
|---|---|
| `server/xiaozhi-server/core/notify_plugin.py` | **新增**。连接表 + HTTP 入口，不动上游业务代码 |
| `tools/notify_patch_app.py` | **新增**。幂等地往 `app.py` 插两行（带 `.bak`，可 `--revert`） |

原理（从源码读出来的，不是猜的）：
- 上游 `core/websocket_server.py:121` 每次连接都 `new` 一个 `ConnectionHandler`，但**没有全局注册表** → 插件用**运行时包装** `ConnectionHandler.handle_connection` 建 `<device_id> → handler` 的表，不改上游文件
- 上游 `core/connection.py:1413` 本来就有 `self.tts.tts_one_sentence(self, ContentType.TEXT, content_detail=text)` —— **服务端主动播报的能力上游本来就有**，只是缺个触发口
- HTTP 走**独立端口 8004**，避开 8000（websocket）/ 8003（OTA + 视觉）

### 接线（两条命令）

```powershell
& "...\python.exe" "...\xiaozhi-deskemoji-agent\tools\notify_patch_app.py"
# 然后重启后台：双击 server\start_server.cmd
```

启动日志里应出现：`active-notify 插件已装载` 和 `主动播报接口是 http://192.168.3.139:8004/notify`

### 用法

```powershell
# 让指定设备开口
curl -X POST http://127.0.0.1:8004/notify -H "Content-Type: application/json" `
     -d "{\"device_id\":\"84:c7:bb:58:17:44\",\"text\":\"你让我总结的项目进展，已经写好了\"}"

# 看谁在线
curl http://127.0.0.1:8004/notify/status
```

服务端返回 `{"ok":true,...}` 即已推入 TTS 队列；设备离线返回 503 并列出在线设备。

### 边界（先知道，别踩）
- **设备离线**：返回 503，不排队（后续可加离线待播队列）
- **设备正在说话时来新播报**：默认**插队**。要改成"打断"或"排队"再调（`docs/06` §九）
- **TTS 出网**：播报文本会经 Edge 合成
- ⚠️ 这个插件**还没跑过一次**（本轮沙箱拦了命令执行），首次启动要看日志确认没报错

## 六、硬件结论：不用再买 ESP32 了

### 你手头够不够？——够，而且不止够

| 板子 | 料 | 结论 |
|---|---|---|
| ① deskemoji（S3N16R8） | **全齐**，已在跑 | 不用买任何东西 |
| ② WROOM-32 紧凑版 | 有板 + MAX98357 功放 + 0.96" OLED；**缺 INMP441 麦 + 喇叭** | **麦明天到、喇叭过两天到 → 闭环** |
| ③ 超级版（带摄像头） | 未购 | **暂缓**（下面说） |

**第二台的形态，我建议这么定**（`docs/10` / `docs/11` 已论证）：
- **先走 `bread-compact-esp32` + 0.96" OLED**：官方原生支持、接线表已给全、无 PSRAM 也稳
- 你清单里那块 **1.54" 240×240 彩屏**也有官方归宿（`bread-compact-esp32-lcd`，`CONFIG_LCD_ST7789_240X240_7PIN`），**但要二选一**（共用 GPIO4/15），而且彩屏更吃 Flash —— 先把 OLED 版跑通，彩屏当第二次折腾
- 无 PSRAM → **唤醒以按键为主**（离线唤醒词吃紧），这是要认的账
- 🎁 顺带：官方这块板型自带 `LAMP_GPIO=GPIO18` 的 MCP「控制台灯」示例，**正好配你清单第 12 项那个继电器**，一行代码不用改

**所以：ESP32 这块不要再买了。** 手头 36 项 + 两块板，够你学很长一段时间。真要花，钱应该花在**耗材**上（杜邦线、面包板、独立 5V 电源），而不是新板子。

### 那"超级版（带摄像头）"呢

`docs/15` 的结论没变：真要上，选 **立创·实战派 ESP32-S3（¥148，官方 `lichuang` 支持，2.0" 触摸屏 + GC0308 摄像头 + 全套音频）**，别选幻尔那套 ¥289。
但**建议往后放**——你现在最缺的不是硬件，是把「设备 → 自建后台 → 主动播报」这条闭环跑通。**闭环没通之前，多一块板只是多一个待办。**

### 树莓派 5 —— 这个方向我赞成，理由说清楚

你说"ESP32 完全熟悉之后再考虑树莓派 5"，**这个节奏是对的**。因为 RPi5 在你这套架构里不是"又一块单片机"，而是**换了个角色**：

| | ESP32 | 树莓派 5 |
|---|---|---|
| 定位 | **终端**（麦克风+喇叭+屏+云台） | **大脑**（跑 LLM/ASR/TTS、跑视觉、跑后台） |
| 算力 | 几百 MHz 级、几百 KB 内存 | 4×2.4GHz ARM64、4/8GB 内存、可接 NVMe |
| 能否刷小智固件 | ✅ 它本来就是干这个的 | ❌ 不能（指令集/外设语义都不同，跟手机同理，见 `docs/12`） |

**RPi5 能替你解决的三件事**（都是现在笔记本在扛的）：
1. **让后台 7×24 独立运行** —— 不用一直开着主力电脑，小智才真正"随时在线"
2. **视觉路线 B 的天然落点** —— `docs/14` 里我推荐的"PC 摄像头 + MediaPipe → 网络下发云台角度"，树莓派挂个 USB 摄像头就是最合适的执行者（**手部 21 点跟踪、物体识别，ESP32 永远做不到，树莓派轻松**）
3. **Home Assistant / 边缘 AI** —— 智能家居联动的正统入口

**要提前知道的三个坑**：
- **电源**：官方要求 **5V/5A（27W）**，用手机充电器会限流降频甚至起不来
- **散热**：必须加主动散热（风扇/散热片），满负载会热降频
- **跑大模型不现实**：8GB 版跑 `qwen3:4b` 也能跑，但慢；**本地 LLM 真正能用的尺寸是 0.5B~1.7B**。所以 RPi5 的价值在"**稳定托管 + 视觉**"，不是"本地大模型"
- 买的话：**8GB 版 + 官方 27W 电源 + 主动散热 + （可选）NVMe HAT**，别买 4GB

### ⚠️ 这一步踩了两个"静默失败"的坑（都已修正并记档）

**坑 1：`MSYSTEM` 让 idf.py 变成"只打警告不干活"**

从 Git Bash 拉起 python → powershell → idf.py 时，`MSYSTEM=MINGW64` 会被一路继承。
而 ESP-IDF v5.5.4 的 `tools/idf.py`（第 914 行附近）结构是：

```python
if 'MSYSTEM' in os.environ:
    print_warning('MSys/Mingw is no longer supported. ...')   # ← 这个分支里没有 main()
elif ...:
else:
    main()
```

**只要 MSYSTEM 存在，idf.py 打印完警告就退出，什么都不编，而且退出码是 0。**
于是脚本以为自己成功了，其实是空跑——第一次"构建成功但找不到产物"就是这个原因。
→ 修法：`stage_a_build.py` 里加 `clean_env()`，剥掉 `MSYSTEM` / `MINGW_PREFIX` 等变量。

**坑 2：`sdkconfig.defaults` 里的行**必须**带 `CONFIG_` 前缀**

我一开始写的是 `OTA_URL="..."`、`BOARD_TYPE_...=y`，没加前缀。
kconfgen 对这种行是**静默忽略**（不报错、不警告），于是 OTA 地址悄悄退回
Kconfig 里的默认值 `https://api.tenclass.net/...`。查了半天才发现。
→ 修法：写成 `CONFIG_OTA_URL="..."`、`CONFIG_BOARD_TYPE_ESP32_S3N16R8_EMOJI=y`。

**顺带两个发现：**
- 仓库里**自带并 git 跟踪了一个 `sdkconfig`**（作者把本地构建配置提交了）。
  ESP-IDF 的取值顺序是 defaults 打底 → 已存在的 sdkconfig 覆盖，所以这个文件**优先级高于 defaults**，
  必须一起改（脚本已加 `patch_existing_sdkconfig()`）。
- `idf.py set-target` 会把已有 `sdkconfig` 重命名成 `.old` 再按 defaults 重生成——
  所以**别在 set-target 之后才去改 sdkconfig**。脚本已改成"有构建缓存就跳过 set-target，
  直接增量 `idf.py build`"（省十几分钟）。

**这一步需要你先做一件事：把 deskemoji 用 USB 数据线插上电脑。**
（当前系统里没有任何 COM 口，设备没连。）

插上后我执行：

```powershell
# 1. 写进 ota_1（不碰 ota_0）
& "...\python.exe" "...\tools\stage_a_build.py" --source-existing --flash COMx

# 2. 切启动分区到 ota_1
# 激活 IDF v5.5.4 后：
python "$env:IDF_PATH/components/app_update/otatool.py" --port COMx switch_ota_partition --name ota_1
```

出问题就 `switch_ota_partition --name ota_0` 十秒回滚。

---

## 八、风险与回滚一览

| 风险 | 应对 |
|---|---|
| 新固件刷坏 | 只写 ota_1，`otatool switch_ota_partition --name ota_0` 十秒回滚；另有 16MB 全片备份 |
| fork HEAD 版本 ≠ 2.0.1 | 先看编译时打印的版本；必要时 checkout 对齐，或连 assets 一起刷 |
| App 超 4MB 分区 | 脚本会检查并告警；超了就得裁资源（LVGL 组件或表情） |
| 设备连不上自建后台 | 串口日志看 `Connecting to ws://...`；核对 IP 与静态绑定 |
| `/notify` 插件出错 | `tools/notify_patch_app.py --revert` 还原 `app.py`；插件是独立文件，删掉即彻底回退 |
| 聊天里贴过的 token | MCP token / GitHub PAT **建议重新生成** |
