# ASR 该用本地还是外部大模型？（2026-10-03 实测）

> 主人三个问题：①有没有必要用外部大模型 ②本地识别准不准 ③外部大模型怎么收费

---

## 一、实测方法（客观，不是猜）

用**火山 TTS 合成标准普通话** → 重采样到 16kHz → 喂给本地 Sherpa → 与原文逐字对比。

测试脚本：`tools/asr_bench.py`（可重跑）

⚠️ **局限性必须说清楚**：TTS 音比真人干净——无噪声、无口音、语速均匀。
**这套测试对本地 ASR 有利**。真人在嘈杂环境、边想边说时会掉更多分。

---

## 二、实测结果：本地 Sherpa（SenseVoice）

| 场景 | 原文 | 本地识别结果 | 字错率 |
|---|---|---|---|
| 日常 | 主人，帮我看一下今天的天气怎么样 | 主人帮我看一下今天的天气怎么样。 | **12%** |
| 口语 | 嗯，那个，你把客厅的灯关一下，然后再帮我倒杯水 | 嗯，那个你把客厅的灯关一下，然后再帮我倒杯水。 | **9%** |
| 数字 | 我明天早上八点要交房租，房租是两千三百五十元 | 我明天早上8点要交房租，房租是**2350元**。 | 36%※ |
| **专有名词** | 小智，帮我打开 **deskemoji** 的表情设置 | 小智帮我打开 **disimmoji** 的表情设置。 | **30%** |
| **专有名词** | 把**舵机**的角度调一下，再试一次 **WorkBuddy** 的任务 | 把**多机**的角度调一下，再试一次 **work bud** 的任务。 | **32%** |

※ 数字那行的 36% 是**我统计方法的锅**：原文"两千三百五十"被正确转成"2350"，
语义完全正确、LLM 也更容易懂，但字面比对照例算成了错。

### 平均字错率 24%，但拆开看是两个世界

| 类别 | 字错率 | 结论 |
|---|---|---|
| **日常口语** | 9~12% | ✅ **完全够用**，那点误差全是标点，LLM 完全能理解 |
| **专有名词** | 30~32% | ❌ **不行**，全错 |
| 数字 ITN | — | ✅ 反而是优点，"两千三百五十"→"2350" 对 LLM 更友好 |

### 错在哪儿（很典型）

| 词 | 识别成 | 说明 |
|---|---|---|
| deskemoji | **disimmoji** | 英文混在中文里，纯中文模型容易糊 |
| 舵机 | **多机** | 同音字 + 生僻词 |
| WorkBuddy | **work bud** | 英文专有名词被拆散了 |

**这三个恰好是火山热词表能解决的**（热词表就是干这个的）。

## 三、要不要用外部大模型？我的建议：**先别急着换，用热词表补短板**

### 成本对比

| 项 | 本地 Sherpa | 火山豆包流式 2.0 |
|---|---|---|
| 费用 | **0**（模型已下好，1.1G） | ~0.9~1 元/小时 |
| 免费额度 | 不限 | 你已开通（有赠送额度） |
| 隐私 | ✅ **音频不出网** | ❌ 音频发到火山 |
| 延迟 | 本地推理，几乎无感 | 网络往返 + 服务端排队 |
| 日常口语 | ✅ 够用 | ✅ 更好 |
| 专有名词 | ❌ 全错 | ✅ **有热词表就能对** |
| ITN 数字规整 | ✅ | ✅ |

### 判断依据

**如果你日常是说"帮我查下天气""打开酷狗""三分钟后提醒我"——本地够用，不用换。**
实测 9~12% 的误差对 LLM 理解毫无影响，而且白嫖、隐私、快。

**如果你经常说专有名词（小智、deskemoji、舵机、WorkBuddy、Ollama）——
那问题不在"本地 vs 大模型"，而在"没配热词表"。**
豆包大模型不配热词表，一样认不对这些词。

### 我的推荐路线

```
第 1 步：保持本地 Sherpa（免费、隐私、快）
         ↓
第 2 步：建一个热词表（5 分钟，见下）→ 切到豆包 2.0 验证专有名词
         ↓
第 3 步：如果热词表解决了 → 日常还是本地，需要说专有名词时切豆包（混合）
         如果觉得还是不够好 → 全切豆包（1 元/小时，一天聊 1 小时 = 30 元/月）
```

## 五、热词表怎么建（无论用不用豆包都值得试）

火山控制台 → **自学习平台 → 热词管理 → 新建热词表**

一行一个词（**最长 10 字**），可用 `词|数字` 设权重 1~10（不写默认 4）：

```
小智
deskemoji
WorkBuddy|8
舵机|8
Ollama
豆包
埃moji
记忆库
待办
```

保存后拿到一个 UUID，填到配置：

```yaml
DoubaoASRStream:
  boosting_table_name: "把那个 UUID 填这里"
```

⚠️ **本地 Sherpa 不支持热词表**（SenseVoice 没有这个机制），
所以热词表只在切到豆包时有效。

## 六、还发现一个可以立刻做的改进：TTS 发音词典

豆包 2.0 TTS 支持 `pronunciation_dict`（**5000 条，原词 ≤9 字**），
修专有词的**发音**——这是让小智**念对**（比 ASR 热词表更直接，AI 已经听对了只是念错）。

值得加的：
```
小智/(xiao3 zhi1)
WorkBuddy/(wer1k ba4 di1)
deskemoji/(desk emoji)
豆包/(dou4 bao1)
Ollama/(o5 la1 ma1)
```

⚠️ 只在 2.0 通道有效，切到 1.0 就用不上。
