## 一、那个"呲"的声音到底是什么

**就是 `main/assets/common/popup.ogg`** —— 小智官方用来提示"我听到了"的音效。

| 项 | 值 |
|---|---|
| 文件 | `firmware/community/main/assets/common/popup.ogg`（1148 字节） |
| 时长 | **480ms**（这就是"呲"的原因——对提示音来说太长了） |
| 采样率 | 16kHz |
| 设计意图 | 原厂是"弹窗提示"音，不是"豆包式轻提示" |

同目录还有 4 个可替换候选：

| 文件 | 时长 | 观感 |
|---|---|---|
| `popup.ogg` | 480ms | ← 现在用的，偏高偏尖 |
| `vibration.ogg` | 792ms | 更长，更不适合当提示音 |
| `exclamation.ogg` | 889ms | 更长 |
| `success.ogg` | 1020ms | 最长，是"成功"提示音 |
| `low_battery.ogg` | — | 低电量，不合用 |

**结论**：现成音效里没有"豆包式轻提示"，**需要自己合成**。
已用 numpy 合成三个候选（正弦双音 + 指数衰减 + 8ms 淡入淡出防爆音）：

| 候选 | 频率 | 时长 | 特点 |
|---|---|---|---|
| A | 880 + 1320Hz | 200ms | 短促温和（**推荐**） |
| B | 1046 + 1568Hz | 280ms | 偏亮，更清脆 |
| C | 660 + 990Hz | 350ms | 低沉柔和 |

试听文件：`tmp/sounds/柔和{A,B,C}_*_x3.wav`（各连放三遍）。
挑中后用脚本写回 `popup.ogg` 即可（注意：改 ogg 要重编译刷机）。

⚠️ **无 AEC 的坑**：本板 0 回放通道，提示音会被麦克风录进去。
所以**越短越好**（200ms 优于 480ms），这也是选合成方案的主要原因。

## 二、慢速仍被打断 —— 找到真正的主战场

上一轮只改了固件 `vad_min_noise_ms`（100 → 800），改善了但没根治。这轮查清了**两层判定**：

```
设备端 AFE ──判定"说完"──► 发 listen stop ──► 服务端立刻停止识别出答案
                              ▲
                     主战场（决定"何时 stop"）
服务端 SileroVAD ──第二道保险（只在 stop 还没来时起作用）
```

证据：
- `protocol.cc::SendStartListening()` 发的消息带 `"mode":"auto"` → **停止时机走的是"设备说 stop"这条路**
- `core/handle/textHandler/listenMessageHandler.py:43` → `conn.client_voice_stop = True`（收到 stop 立即置位）
- `core/providers/vad/silero.py:28` → `min_silence_duration_ms` **默认 1000**。
  ⚠️ 后半句是**当时的状态**：那会儿 `VAD:` 段压根没写、一直在吃默认值；
  后来补上了配置段（见下表现值），现在吃的是配置里写的 **700**。

### 修复

| 层 | 参数 | 原 | 现 | 生效方式 |
|---|---|---|---|---|
| 固件 AFE | `vad_min_noise_ms` | 800 | 1400（实验值，**未回退**） | 重编译刷机 |
| 服务端 SileroVAD | `min_silence_duration_ms` | 1000（默认） | **700（官方默认，已回退）** | 改配置重启 |
| 服务端 SileroVAD | `threshold_low` | 0.2（默认） | **0.3（官方默认，已回退）** | 改配置重启 |

> ⚠️ **2026-10-03 23:59 更正（与磁盘/配置实际取值对齐）**
> 服务端这两个此前记的 `1400 / 0.1` 是**无官方依据的实验值**，现已回退官方推荐的 `700 / 0.3`。
> 另：配置里 VAD 段当时把 `threshold` / `threshold_low` / `min_silence_duration_ms`
> **各写了两遍**（YAML 重复键后者生效），且两组注释互相矛盾，已去重为一组。

**`threshold_low` 为什么动过、又为什么退回来**（`silero.py:91`）：

```python
if speech_prob >= self.vad_threshold:      is_voice = True    # ≥0.5 有声音
elif speech_prob <= self.vad_threshold_low: is_voice = False   # ≤0.3 静音
else: is_voice = conn.last_is_voice                         # 中间区延续上帧
```

说话中的换气停顿，语音概率常掉到 **0.1 附近**。
当时的想法是"把下限压到 0.1，停顿就不会被判静音"——**这个推理是错的**：
下限压到 0.1 等于几乎取消了迟滞带，判定变得极不稳定，实测反而更容易断句。
官方给 0.3 是有道理的，已回退。

### 代价

回退后：说完整句后等 **0.7 秒**（官方默认）才开始识别，比之前的 1.4 秒利落。
嫌抢话就在管理台把 `min_silence_duration_ms` 调大（说话慢可到 1000），**不用刷机**；
固件那个 `vad_min_noise_ms` 管理台改不了，要改必须刷机。
