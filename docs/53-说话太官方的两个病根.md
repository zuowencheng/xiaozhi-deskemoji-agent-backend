# 小智"说话太官方"根因与修复（2026-10-03 19:00）

## 一句话结论

跟音色 `zh_female_vv_uranus_bigtts` **一点关系都没有**。
是上游 `config.yaml:204` 那段"台湾00后机车女友"人设一直没被覆盖，
加上问模型时**工具压根没注册**，模型只能靠猜 → 于是又长又官方。

## 病根 ①：人设没覆盖

上游 `config.yaml:204-217`：

```yaml
prompt: |
  你是小智/小志，来自中国台湾省的00后女生。讲话超级机车，
  "真的假的啦"这样的台湾腔，喜欢用"笑死""是在哈喽"等流行梗……
```

而 `data/.config.yaml`（实际生效配置）**从没有 `prompt:` 键** → 一直沿用官方设定。

**为什么之前只改 `agent-base-prompt.txt` 不管用**：
人设 prompt 被模板包进 `<identity>{{base_prompt}}</identity>`，
**优先级高于模板里的风格规则**。风格要求写在 `core_rules` 里，
被 identity 压住了 —— 必须改 `prompt:` 本身。

### 已做修复

`data/.config.yaml` 新增顶层 `prompt:`，覆盖为「快、准、有人味」的桌面搭档人设，
明确写了"台湾腔和'机车'这套全部不要"。

## 病根 ②：问模型时工具没注册

`plugins_func/functions/llm_switch.py` 早就写好了 `list_llms` / `switch_llm`，
但 `Intent.function_call.functions` 列表里**没有 `llm_switch`** → 模型手里没工具。

**「你用的什么大模型」这种问题，模型答不上来就靠猜**
→ 表现为"扯来扯去、铺陈一大段"。

### 已做修复

`Intent.function_call.functions` 加 `- llm_switch`。

启动日志已验证生效：
```

```

## 附带修的 bug：change_role 会冲掉全部规则

`change_role.py` 原来调 `conn.change_system_prompt(new_prompt)`，
而 system prompt 是 `agent-base-prompt.txt` 模板 + 人设 + 时间天气 + 记忆规则 + core_rules
**渲染出来的**。直接塞一段人设文字 = 把其余规则**全部丢掉**。

表现：换了角色之后小智立刻变得又长又客套 —— "官方"有一部分是这么来的。

**已修**：只换人设这一层，重新走一遍模板渲染：

```python
enhanced = conn.prompt_manager.build_enhanced_prompt(
    new_prompt, conn.device_id, conn.client_ip,
    emoji_enabled=(getattr(conn, "features", None) or {}).get("emoji", True),
)
conn.change_system_prompt(enhanced or new_prompt)
```

顺手把 `prompts["机车女友"]` 的原文也换了（key 保留，避免破坏历史调用习惯）。

## 踩坑备忘：改配置 ≠ 生效

`_initialize_components()` **只在设备连接建立时读一次 prompt**（`connection.py:623`）。
改完 `data/.config.yaml` 必须重启后台，否则旧配置继续跑。

重启必须用绕开 job 的方式（见 MEMORY.md 约定 6）：

```bash
python tools/start_services.py --stop
python tools/start_services.py --explorer --wait 25
```

## 新增工具：tools/watch_device.py

判断设备稳不稳的**唯一正确方式**（全程不碰串口）：

```bash
python tools/watch_device.py --minutes 15
```

原理：`OTA请求设备ID` 只在设备开机时发生 → 计数零增长 = 稳定，增长 = 在重启。
⛔ 碰串口（`tools/read_serial.py`）会触发 `rst:0x15` 复位，
**判定设备状态前绝对不许碰串口**。
