## 二、我补充的两条（文档遗漏）

### R5 · ⭐ 两套执行器并存 —— 这正是主人问的"是不是在空跑"

```
notify_plugin.py:1332-1333
    if notify_cfg.get("exec_enabled", True):          # ← 未配置 = True = 默认开
        _TASKS.append(asyncio.create_task(_execute_inbox_loop(notify_cfg)))
```

**常驻执行器 `_execute_inbox_loop` 是开着的，而且实时**：循环扫 inbox → 命中 `状态：pending` → 立刻 `_ack_task()` 播回执（"收到了正在干"）→ `asyncio.create_task(_run_one_task(f))` → `pc_agent.execute_task_file`。

所以真实链路是：

```
小智说话 → pc_run_task 写 inbox/task-*.md
        → 常驻执行器【秒级取件 + 立即播回执】   ← 实时通道，已经存在
        → 执行 → 写结果 → 移 done/ → watcher 播报结果
```

而那个每小时的 automation，起来时 inbox **几乎总是空的**（活早被常驻执行器干完移走了），于是执行它 prompt 的第 1 条：「一个都没有，立刻结束，不要输出」→ **空跑**。

> **主人的直觉是对的：它确实在空跑。**

**附带的真实风险（比空跑更值得处理）**：automation 的取件条件**不检查 `状态：pending`**（只读 `task-*.md` 就干），而常驻执行器是先加 `_EXEC_RUNNING` 再改状态。存在一个竞态窗口：automation 若在常驻执行器改状态前读到同一文件 → **同一任务被执行两遍**。automation 的 prompt 里写了"必须移动不能复制"只防了自己重复执行，没防跨执行器撞车。

### R6 · 遥测数据**已经产生**，只是没落盘

```python
# pc_agent.py:1221（自测入口，直接打印）
print("ok =", r["ok"], "| 步数 =", r["steps"], "| 耗时 =", r["ms"], "ms")

# pc_agent.py:1163-1167（真实入口）
out = run_agent(task_for_agent)
_rewrite_status(path, "done" if out.get("ok") else "failed", result)   # ← 只传了 result
```

`run_agent` 返回值里**本来就有 `steps` 和 `ms`**，但真实入口只把 `result` 写回任务单。
→ P1-⑦「补遥测」的落点非常精确：**给 `_rewrite_status` 加两个参数即可，不用改执行内核**。

## 七、长任务话术（2026-10-04 01:07，主人要的"久就先说一声"）

主人诉求：任务如果**预估要跑一会儿**，小智先回一句"这个可能要久一点，先忙别的"；
干完了再通知小智 → 小智通知主人。

**结论：完全可行，已实现。** 三句话构成完整闭环：

| 时机 | 说什么 | 状态 |
|---|---|---|
| ① 取件瞬间（预判要久） | "收到，XXX。这个可能要花点时间，你先忙别的，弄完我叫你。" | ✅ 新增 |
| ①' 取件瞬间（普通活） | "好的，正在处理：XXX"（原话术不变） | ✅ 保留 |
| ② 跑过 60s 还没完 | "那个任务还在弄着，快好了，弄完我马上叫你。" | ✅ 新增（配置 `notify.long_task_nudge_sec`） |
| ③ 干完 | 结果摘要（由取件 watcher 播） | ✅ 原有 |

**怎么判断"要久"**：关键词粗判（`_looks_long_task`）。取向是**宁可漏判也别误判**——
多说一句代价很小，让主人干等 3 分钟不知道有没有接单代价很大。

⚠️ **踩过的坑**：最初词表里放了「所有 / 全部」，真实回扫发现它把
「显示桌面（最小化所有窗口）」「关掉所有浏览器」这种 1 步操作也判成要花时间——
开口就说"要久一点"很傻。已删掉这两个词，长任务占比 30% → 23%，
剩下的都是真·排查/总结/统计类。

### 验证

  任务已结束就不再打扰）
