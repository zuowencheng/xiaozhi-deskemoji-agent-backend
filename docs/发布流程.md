# 发布流程（Release SOP）

> 两个仓库、两条发布线。**固件**跟硬件走，**后端**跟软件走。

---

## 0. 两个仓库

| 仓库 | 内容 | 地址 |
|---|---|---|
| `xiaozhi-deskemoji-agent` | **固件**（ESP-IDF 工程，独立 git 仓：`firmware/community/`） | https://github.com/zuowencheng/xiaozhi-deskemoji-agent |
| `xiaozhi-deskemoji-agent-backend` | **后端**（本根仓：服务端 + bridge + tools + deploy） | https://github.com/zuowencheng/xiaozhi-deskemoji-agent-backend |

> 根仓里 `firmware/community/` 被 `.gitignore` 排除——它是**独立仓库**，根仓只通过 `firmware/patches/` 留改动补丁，避免嵌套子仓。

## 一、固件发布

**1. 改版本号**（唯一来源）
```
firmware/community/CMakeLists.txt :  set(PROJECT_VER "X.Y.Z")
```
> ⚠️ 版本串不变 → `compile_time` 不更新；设备握手比对的是 `elf_sha256`，不是时间戳。

**2. 编译**（PowerShell，唯一正确姿势）
```powershell
cd firmware\community
$env:MSYSTEM=$null
eim.exe run 'idf.py build' v5.5.4
```
> 判据看 stdout 出现 `Project build complete`，**别信退出码**。

> ⚠️ **两个必踩的坑（2026-10-24 实踩）**
>
> **坑 A：PowerShell 管道死锁。** 写成 `eim.exe run 'idf.py build' v5.5.4 2>&1 | Select-Object -Last 40`
> 会让编译卡死 —— `ccache` 挂 0 CPU 十几分钟不干活，build 目录一个字节都不写。
> 正确姿势是用 `Start-Process` 把输出直接重定向到**文件**（不经 PS 管道）：
> ```powershell
> $env:MSYSTEM = $null
> $p = Start-Process -FilePath "eim.exe" -ArgumentList 'run "idf.py build" v5.5.4' `
>        -WorkingDirectory $wd -RedirectStandardOutput build_out.txt -RedirectStandardError build_err.txt `
>        -NoNewWindow -PassThru
> $p.WaitForExit()
> ```
> 注意 `-ArgumentList` 必须整串传（`'run "idf.py build" v5.5.4'`），拆成数组会被 eim 解析成
> `unexpected argument 'v5.5.4'`。另外若环境里同时存在 `HTTP_PROXY` 与 `http_proxy`，
> `Start-Process` 会报"已存在的关键字"而失败，调用前先 `Remove-Item Env:http_proxy`。
>
> **坑 B：ccache 本身会卡死。** 即使绕开坑 A，ccache 仍会 0 CPU 挂死在编译中途
> （缓存目录 `%LOCALAPPDATA%\ccache` 的 `lock/` 会留下被强杀进程的锁）。
> 根治办法是把 ccache 从编译命令里摘掉：
> ```bash
> sed -i 's/^CCACHE_ENABLE:UNINITIALIZED=1$/CCACHE_ENABLE:UNINITIALIZED=0/' build/CMakeCache.txt
> sed -i 's/command = ccache \${LAUNCHER}/command = ${LAUNCHER}/g' build/CMakeFiles/rules.ninja
> ```
> 摘掉之后 124 个目标一次跑完，不再卡。

**3. 刷机验证**
```powershell
&C:\Espressif\tools\python\v5.5.4\venv\Scripts\esptool.exe --chip esp32s3 --port COM4 -b 460800 write_flash 0x500000 build\xiaozhi.bin
```
> `ota_0(0x100000)` 是原厂保命区**不动**；新固件刷 `ota_1(0x500000)`。

**4. 打标 + 推**
```bash
cd firmware/community
git tag -a vX.Y.Z -m "vX.Y.Z"
git push mine main refs/tags/vX.Y.Z
```

**5. 造发布包** → 放 `dist/firmware-releases/vX.Y.Z/`
```
vX.Y.Z/
├── xiaozhi.bin        ← 用户直接刷
├── xiaozhi.elf        ← 调试（addr2line 回溯用）
├── SHA256SUMS.txt     ← 校验
└── README.md          ← 版本说明（含刷写命令）
```

**6. 在 GitHub 建 Release**
- Tag：选刚推的 `vX.Y.Z`
- 标题：`vX.Y.Z · <一句话主题>`
- 说明：把该版本 `README.md` 内容粘进去
- 附件：上传 `dist/firmware-releases/vX.Y.Z.zip`
- `dist/firmware-releases/RELEASE_NOTES.md` 里有**全部版本**的说明汇总，可整段复制

## 二、后端发布

**1. 改版本标识**（建议）：根 `README.md` 顶部 + `server/README.md`

**2. 自检**
```bash
python tools/paths.py            # 路径解析是否正常
python tools/doctor.py           # 体检
python tools/gen_mcp_settings.py --print   # MCP 配置是否按本机生成
```

**3. 打标 + 推**
```bash
git add -A
git commit -m "release: vX.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z"
git push mine main refs/tags/vX.Y.Z
```

**4. 建 Release**：同固件，附件上传打包好的后端 zip（可选）。

---

## 三、发布前检查单（每次都要过）

- [ ] 无任何**真实 API Key** 进仓库（`data/.config.yaml`、`bridge/.env` 已被忽略）
- [ ] 无本机绝对路径（跑 `tools/paths.py` 确认解析；`xiaozhi.local.json` 不进库）
- [ ] 无大文件（`dist/`、`models/`、`*.bin`、`build/` 已被忽略）
- [ ] `git status` 里没有 `_archive/` 或 `dist/` 的内容
- [ ] README 与 CHANGELOG 已更新
- [ ] 版本号三处一致：`CMakeLists.txt` / README / tag

## 四、设备端配置（交给使用者）

1. 配网后填服务端地址：`ws://<本机IP>:8000/xiaozhi/v1/`
2. OTA 地址：`http://<本机IP>:8003/xiaozhi/ota/`
3. 详见 `docs/配置指南.md`
