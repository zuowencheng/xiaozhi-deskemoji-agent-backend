## 一、舵机不动的根因（已用串口日志钉死）

### 铁证

```
I (20378) EmojiController: AnimationTimerTask: 准备执行随机动画
I (20378) EmojiController: AnimationTimerTask: 已发送随机动画消息
I (20378) EmojiController: AnimationTask: 收到动画消息，类型: 27, 参数: 0
I (20378) EmojiController: 执行随机动画，类型: 0
W (20388) EmojiController: ExecuteRandomAnimation: 屏幕或眼睛对象不存在   ← 每次断在这里
```

另有 `W (8108) EyeCenter: 屏幕或眼睛对象不存在`。

### 代码层面的因果链

`emoji_controller.cc` 里**每个 `Execute*Animation` 都是同一副骨架**：

```cpp
void EmojiController::ExecuteRandomAnimation() {
    ...
    // 第 677 行：开头就查表情屏
    if (emoji_screen_ == nullptr || left_eye_ == nullptr || right_eye_ == nullptr) {
        ESP_LOGW(TAG, "ExecuteRandomAnimation: 屏幕或眼睛对象不存在");
        return;                       // ← 这里 return 了
    }
    switch (type) { ... }
    ...
    servo_controller_->HeadMove(...);  // 第 804/858 行：舵机动作在 return 之后，永远执行不到
}
```

共 **20 个动画函数**都是这个结构（678 / 728 / 876 / 1001 / 1154 / 1273 / 1373 / 1476 / 1581 / 1718 / 1818 / 1914 / 2033 / 2135 / 2270 / 2394 / 2486 行 …）。

### 为什么 `emoji_screen_` 一直是 nullptr

- `EmojiController::Initialize()`（第 31–64 行）**只创建了 `AnimationTask` 和 `AnimationTimerTask` 两个任务**，**没有创建表情屏**。
- `CreateEmojiScreen()`（第 266 行）**只在长按 BOOT 进"表情模式"时被调用**（`emoji_board.cc` 的 `OnLongPress` → `SwitchScreen(true)`）。
- `is_emoji_mode_` 初值 `false` → 开机默认文字屏 → 表情屏**压根不存在**。

### 结论

**"舵机不动"和"表情不动"是同一个根因、一个修复点。**
舵机不是坏，是它的动作被写在了一段永远走不到的死代码后面。

## 二、舵机的四条驱动链路（现状）

| # | 链路 | 触发方式 | 是否受表情屏连坐 | 现状 |
|---|---|---|---|---|
| 1 | `EmojiController` 动画（`PlayAnimation` → 队列 → `Execute*Animation`） | idle 随机动画 / AI 情绪 | **✅ 被连坐** | ❌ 全被 return 挡掉 |
| 2 | `EmotionResponseController` 直接调舵机（`HeadUp/HeadNod/HeadRoll`…） | AI 回复里的情绪关键词 | ❌ 不受影响 | ⚠️ 理论能动，仅 6 个动作走这条 |
| 3 | `GestureSensor`（PAJ7620） | 手在传感器上方 5–15cm 挥手 | ❌ 不受影响 | ✅ 传感器初始化成功、任务已跑（prio 7） |
| 4 | 长按 BOOT → `HeadCenter()` | 长按 BOOT | ❌ 不受影响 | ⚠️ 只是归中，在中心位看不出动 |

**关键：链路 3（挥手）完全独立于表情屏，是验证舵机硬件的黄金手段。**

**桌宠身份怎么定？**

## 四、修复方案（待执行）

### 方案 1：自愈式懒创建（推荐，改动最小）

在 `AnimationTask` 收到动画消息后、执行 `Execute*Animation` 之前，插一段"确保表情屏存在"：

```cpp
if (emoji_screen_ == nullptr) {
    DisplayLockGuard lock(display_);
    CreateEmojiScreen();
    lv_scr_load(emoji_screen_);
}
```

一次修好表情 + 舵机。副作用是 idle 随机动画会让屏幕切到表情屏。

### 方案 2：彻底解耦（最正确，改动大）

把 20 个 `Execute*Animation` 里的**舵机动作全部提到 nullptr 检查之前**。
理由：舵机是独立物理输出，不该因为屏幕状态被跳过。
代价：改动面大，回归风险高。

### 方案 3：两件都做

先解耦舵机（保证舵机永远能动），再决定表情屏的创建策略（按用户拍的形态走）。
