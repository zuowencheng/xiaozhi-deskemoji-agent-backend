## 二、供电三问（结论 + 待主人实测）

### Q1：USB 供电够不够？

| 负载 | 电流 | USB 口给不给得起 |
|---|---|---|
| ESP32-S3 + WiFi | 峰值 ~350mA（3.3V，约 0.5W） | ✅ 随便给 |
| **2× MG90S 舵机** | 单个空载 ~100mA，**动作/堵转可达 1A** | ❌ **不够稳** |

- 电脑 USB 口通常限流 **500mA / 900mA**；两个 MG90S 只要一起动，5V 轨就被拉低，
  加上板载走线/接插件的压降，舵机端可能只剩 4.x V → **"没劲、发抖、不动"**。
- 这也解释了主人的观察 3（见下）。
- **建议**：舵机 5V **独立供电**（5V/2A 模块，**必须与主板共地**），
  或在舵机 V+/GND 就近并 **1000µF 电解 + 0.1µF 瓷片**。

### Q2：电池"没有识别"

- `board_config.h` 里**没有任何电池 ADC 引脚**；本板目录里**没有** `power_manager.h` /
  `adc_battery_monitor.*`；串口启动明确打 `Display: Power management not supported`。
- → **固件里一行电池电量代码都没有**。这不是"软件坏了"，是**压根没实现**。
- 要显示电量，需先确认硬件：板子上**有没有**把电池电压分压到某个 ADC 脚（常见 GPIO1/2/3），
  有就挂 `adc_battery_monitor`，没有就得自己加分压电阻。
- **待主人确认**：电池是焊在板上的还是接插件？板上有几个引脚标 BAT/ADC？拍照即可。

### Q3：电池初始化动一下、USB 不动

- **同一份固件、两种供电，表现不同 → 只可能是供电差异，不可能是代码分支。**
- 与 Q1 同源：USB 那条路 5V 更"软"，舵机从冷态起转需要的启动电流更大，拉不动就干脆不动。
- **验证手段（已就绪）**：`SERVO_BOOT_SELFTEST=1` 让每次开机必做一次左15°→右15°→回中。
  - 电池 & USB **都能看到摆** → 供电没问题，之前的"不动"是别的原因
  - 电池能看到、USB 看不到 → **坐实 USB 供电不足**
  - **两种都看不到但日志正常** → 舵机接线/V+ 供电断了

## 三、音乐：开源方案到底"连哪里"（主人问的"目录还是连接"）

**答案：两条路都有，而且都不是"扫码读酷狗缓存"。**

### 路线 A：服务端本地曲库（**指定一个目录**）

- 配置：`config.yaml` → `plugins.play_music.music_dir: "./music"`
  → 绝对路径 `server/xiaozhi-server/music/`
- 行为：递归扫 `.mp3 / .wav / .p3` → 用 `difflib` 按歌名模糊匹配 → 走**服务端音频通道下发** → **设备喇叭播**
- 实测日志（10-02 21:03）：
  `本地曲库为空（music_dir=…\xiaozhi-server\music，文件数=0），跳过播放，改为文字回复`
  → 小智回"我的本地曲库还是空的哦"
- **用法：往那个目录丢 mp3 就能点歌。** 目录为空是唯一原因。

### 路线 B：固件云端流式（**连接一个云端服务**）

- `boards/common/esp32_music.cc:297`
  → `http://http-embedded-music.miao-lab.top:2233/stream_pcm?song=<歌名>&artist=<歌手>`
  （第三方 **"喵波音律 MeowEmbeddedMusicServer"**，代码里留了 QQ 群 865754861）
- 行为：云端返回音频 URL → 设备下载 MP3 流 → **本地 MP3 解码** → **设备喇叭播**
- 触发工具：`self.music.play_song / play / stop_song / pause_song / resume_song / set_display_mode`
  （`mcp_server.cc:127-219`；`Board::Board()` 里 `music_ = new Esp32Music()`，所有板子都注册）
- **需要公网可达 miao-lab.top:2233**；不通就点歌失败。

**→ 按主人指示：两条都**原样保留，不做改造**。**
