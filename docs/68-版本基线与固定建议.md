## 二、为什么"服务端能固定，固件不能"

### ✅ 服务端现在固定，理由是充分的

1. **能力已经成型**：33 个 MCP 工具，该有的都有了（文件/桌面/任务/记忆/待办/音乐/搜索/网页/命令）
2. **架构已经定型**：自研能力走 MCP 而非改服务端源码 → **上游升级不会覆盖我们**
   - 本轮已从 `functions` 列表摘掉 `memory_tools` / `todo_tools` / `pc_music_control` 三个插件版
   - 服务的自研部分收缩到 `bridge/`（三个 MCP Server），与上游解耦
3. **有回滚手段**：`git tag v0.1-baseline` + 配置备份 `.bak-20261006`

### ⚠️ 固件现在固定 = 固定一个"过渡态"

固件还踩在三个未定的前提上：

| 前提 | 现状 |
|---|---|
| 板级目录 PR 进上游 | **还没提**（板子是买的，可复现条件已满足，但还没写 PR） |
| ESP-IDF 6.x 迁移 | 本机已装 v6.1，但**还没迁**，我们跑在 5.5.4 |
| 极薄 patch 成型 | 只做了 2 步（删诊断代码、VAD 挪 Kconfig），还剩 2 个可甩的没做 |

**这时候"定版"，固定的是一个注定要被替换的形态。** 等 PR 有结果（合入 or 走极薄 patch）再定，才有意义。

## 三、我的建议（分两层）

### 现在就固定（已完成）

```
服务端 + MCP + 脚本 + 文档  →  tag v0.1-baseline
```

**以后每次改动先 commit**，命令就三行：

```bash
git add -A
git commit -m "一句话说明改了什么"
git status        # 确认干净
```

回滚：`git checkout v0.1-baseline -- <路径>`，或看差异 `git diff v0.1-baseline`。

### 固件：等这两件事之一落地再定版

| 触发条件 | 定版动作 |
|---|---|
| 板级目录 PR **被合入** | 刷官方固件 + IDF 6.x，之后固件侧零维护 |
| PR 被拒 / 挂起超 4 周 | 走极薄 patch，压到 4 个接触点后打 tag |

在这之前，固件每次改动：
```bash
cd firmware/community
git diff > ../patches/0001-firmware-changes.patch   # 当前 22 文件 / 89 KB
```

## 五、⚠️ 踩到的两个坑（记下来别再踩）

1. **`.gitignore` 不支持行尾注释**
   写 `server/xiaozhi-server/models/  # 1.1GB` 会把整行当路径 → **忽略失效**。
   注释必须单独一行。我是靠 `git check-ignore -v` 才发现的。
2. **`git check-ignore` 对已进索引的文件不报**
   文件被 `git add` 过之后，要加 `--no-index` 才看得到规则匹配。
   另外 Git Bash 的 `cp` 在这台机器上不落盘 —— 备份改用 Python `shutil.copy2`。
