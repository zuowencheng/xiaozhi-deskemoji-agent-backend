## 一、先记住三条硬边界（决定一切）

| # | 边界 | 含义 |
|---|---|---|
| 1 | **MCP 只能搬「LLM 主动调用」的能力** | 搬不动"服务端主动说话"（主动播报 / 到点提醒 / 待办巡检） |
| 2 | **固件层永远搬不走** | MCP 协议够不到固件内部（任务栈 / UI / 板级外设 / 唤醒词） |
| 3 | **但边界 1 可以用「上游插件」绕过** | 插件签名带 `conn`，拿得到连接就能主动发 TTS → 也不用改核心 |

👉 推论：**"不再维护 fork" 的目标 = 把改动压缩到 ①板级目录（贡献上游）②插件/新增文件（抗升级）③独立 MCP 进程（零耦合）**

## 三、贡献官方：能做，但要挑对东西

### ✅ 高概率被接受（上游明确欢迎）
| 资产 | 形式 | 说明 |
|---|---|---|
| `esp32-s3n16r8-emoji` 板级目录 | PR 到 78/xiaozhi-esp32 | 上游有 `boards/README.md` 专讲如何适配新板，**这是最标准的贡献形式** |
| 表情屏 / 舵机 / 手势驱动 | 含在板级目录 | 上游已有 `electron-bot` 这类带舵机的板，有先例 |
| 中文文档 / FAQ 补漏 | PR | 低成本刷存在感，建立信任 |

**PR 前必须满足的硬条件**（上游惯例，缺一会被打回）：
1. **板子要能买到** —— 自焊的唯一原型机很难过审，得给出购买链接或开源 PCB
2. 提供**实物照片 + 接线表 + 编译验证**
3. 代码符合上游 lint / 命名规范
4. 一个 PR 只做一件事

### ⚠️ 大概率不会被接受（别浪费时间）
- **PC 控制类**（pc_control / pc_music_control）：超出"设备端固件"职责，上游不会合
- **深度定制的人格/提示词**：属于个人配置
- **我们改的核心逻辑**（asr 截断修复、唤醒去重等）：除非能证明是通用 bug，否则按 issue + PR 单独提

### ❌ 不该提的
- 含敏感 key / 个人路径 / 本地 IP 的任何文件（推之前必查）

### 💡 更现实的路线：发成独立 MCP 而非合入固件
PC 控制这种"超纲能力"，**发布成独立 MCP Server 的价值 > 提 PR**。
理由：MCP 是开放标准，一次发布，小智 / Claude / 任何支持 MCP 的客户端都能用，**受众远大于小智用户**。

## 四、商业化：能做什么、不能做什么

### 先说结论
**能收费的不是代码，是「整合度 + 省事 + 垂直场景」。**
上游是开源协议（MIT / Apache 系），你卖基于它的改造成品**合规**（保留声明即可），但**用户没有付费义务**——护城河不在代码。

### 可收费的四层（按可行性排序）

| # | 形态 | 为什么能收 | 门槛 |
|---|---|---|---|
| 1 | **成品硬件套件**：桌宠外壳 + 屏 + 双舵机 + 预烧固件 + 电源 | 用户买不到"开箱即用的会动的桌宠"；硬件天然有壁垒 | 需要结构件 / 小批量生产 / 售后 |
| 2 | **一键部署包 + 配置服务**：小智自建服务端 + 24 个 MCP 工具 + 免打扰/提醒/待办全套 | 自建服务端是最大的劝退点，能把它变成"双击就跑"极有价值 | 部署脚本稳定性（我们现在已有 watchdog 基础） |
| 3 | **PC 语音控制套件**（付费 MCP 插件） | 市面上"语音控制 Windows 桌面"成熟方案极少，我们有 20+ 工具实测可用 | 需要跨机通用化（现在是绑定本机路径） |
| 4 | **垂直场景方案**：老人陪伴 / 儿童陪伴 / 桌面助理 | 场景溢价高，客户为"解决具体问题"付钱不为"功能"付钱 | 需要打磨场景体验 |

### 不太建议的
- **卖固件本身**：开源协议下争议大，且用户可自己编译
- **大而全的"AI 助理"**：竞争红海，没有差异化
- **纯 To C 订阅**：小智用户群偏极客，付费意愿低

### 一个务实的起步建议
先做 **#2 一键部署包**（成本最低、复用现有资产最多、可立刻验证有没有人愿意付钱），
用它验证需求 → 有正反馈再投 **#1 硬件套件**（最重但壁垒最高）。

**判断**：设备侧 Wi-Fi 没连上（与"屏幕提示没有连接网络"一致）。
ESP32-S3 **只支持 2.4 GHz**，本机切到 5G 是强信号——网络重置很可能动到了路由器/频段的配置，
而设备 NVS 里存的仍是旧配网信息，不会自动跟随变化。

**处置**（需主人动手，我们不碰串口）：
1. 确认路由器 **2.4G 的 SSID / 密码**是否变过（对比 `HW-ZooKeeper` vs `HW-ZooKeeper_5G`）
2. 没变 → 直接给设备断电重启，让它重连
3. 变了 → 重新配网：进配网模式 → 连设备热点 → 浏览器开 `192.168.4.1` 填新 Wi-Fi 与后端地址 `ws://192.168.3.139:8000/xiaozhi/v1/`
4. 验证：不用碰串口，看服务端日志出现 `设备上线: 84:c7:bb:58:17:44` 即可
