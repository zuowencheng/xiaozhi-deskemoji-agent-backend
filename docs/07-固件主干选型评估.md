# 07 · 固件主干选型评估：官方版 vs 社区版

> 触发需求：**需求 2**——手头还有多块配件和板子（含一块 ESP32），后续都要装小智，
> 希望一次选对主干，减少后续重复劳动，并支撑长期迭代。
> 评估日期：2026-10-02 ｜ 关联文档：`05-固件升级评估与回滚方案.md`

---

## 一、结论

**以官方 `78/xiaozhi-esp32` 作为唯一主干（trunk），社区版降级为"素材库"，不在其上做任何新投入。**

| 维度 | 官方版 `78/xiaozhi-esp32` | 社区版 `TranBinh2311/...-taibai` |
|---|---|---|
| 本项目定位 | **唯一主干** | 仅参考素材（抄引脚、抄驱动） |
| 手头这块 deskemoji | 要一次性移植板型 | 开箱即用 |
| 后续第 2、3 块板子 | 加一个 board 目录 | 每次从零适配 |
| 上游更新 | 活跃（v2.5.0，2026-09-10） | **1 次提交后停更**（2026-06-28） |
| 长期技术债 | 线性增长 | 复利增长 |

一句话：**现在多花半天到一天做移植，换掉未来每块板子都要重复的适配劳动，并且永远跟得上上游。**

---

## 二、为什么是官方版（三条硬理由）

### 1. 多板子 = 官方版的结构性优势

官方仓库的板级抽象是成熟且被验证过的（70+ 板型）：

```
main/boards/
├── esp-box-3/
├── lichuang-dev/
├── esp32-s3-devkitc-1/
└── <你的新板子>/        ← 每块板 = 一个目录（引脚配置 + 外设初始化）
```

**加一块新板子的成本 ≈ 加一个目录 + 在构建脚本里注册**。这是"减少后续工作量"的关键机制。

社区版是**单板 fork**，整棵树只为 `esp32-s3n16r8-emoji` 服务，**没有可复用的板级框架**——
后续那块 ESP32 要接进来，等于从零搭一遍。

### 2. 停更的 fork 是负资产

- 官方：27.9k star，持续迭代（新唤醒词、声纹、显示框架、MCP 协议更新）
- 社区版：1 次提交，**已停更**

在停更的 fork 上加功能，等于把自己和上游越拉越远。将来想回头合并官方新特性，
成本只会越来越大——这是技术债的复利。

### 3. 后续那块 ESP32，官方直接支持

官方覆盖 ESP32-C3 / S3 / P4 及大量现成板型。那块板子**很可能选个相近板型改引脚就能编**，
移植量接近零。这条路在社区版上完全不存在。

---

## 三、代价（要认账的部分）

移植到官方树要搬这几样：

| 要搬的东西 | 来源 | 难度 |
|---|---|---|
| `esp32-s3n16r8-emoji` 板级定义（引脚映射 + 外设初始化） | 社区版仓库 | 低（照抄 + 对引脚） |
| **PAJ7620U2 手势驱动** | 社区版 | 中（官方树不保证有） |
| 音乐功能 | 社区版 / `Maggotxy/xiaozhi-esp32-music` | 中 |
| OLED 表情/资源 | 社区版 `assets` 分区 | 低 |

⚠️ **最大的坑**：手头固件是 2.0.1，官方已到 2.5.0，**跨 5 个次版本**，
板级 API 大概率变过。移植时不能无脑照抄，要按新接口改。

## 四、打法建议（分阶段，别一次全动）

**原则：不要在社区版上做任何新投入（死路），但也不要现在就急着重刷（引入第二个变量）。**

| 阶段 | 动作 | 说明 |
|---|---|---|
| **① 现在** | 装 ESP-IDF（进行中）+ 拉官方 v2.5.0 作为 baseline，在**官方树上**把 deskemoji 板型适配出来，编译通过 | 只在本地，**不刷机**，零风险 |
| **② 验证** | 编译产物刷到**空闲的 ota_1**，逐项验（屏/麦/喇叭/手势/舵机/联网/唤醒） | 坏了 `rollback_app.cmd` 10 秒回来 |
| **③ 之后** | 官方树成为唯一 trunk，每块新板子都往这棵树上加 board | 成本线性 |
| **④ 长期** | 定期 `git fetch upstream` 合并官方更新 | 保持不落后 |

## 五、风险与前提

1. **4MB app 分区上限**：官方固件功能更多（esp-sr + LVGL），编译后可能逼近 4MB。
   对策：`menuconfig` 裁剪用不到的功能；必要时调整分区表（但会动到 `assets` 区，谨慎）。
2. **回滚保障已就绪**：`ota_1`（0x500000）目前为空，`hardware/reports/rollback_kit/` 三层保险可用。
3. **后续那块 ESP32 的前置条件**：小智要跑起来，板子需要**足够的 Flash + PSRAM**。
   经典 ESP32-WROOM 无 PSRAM 会吃紧。**需要先确认型号/配置再判可行性**。
