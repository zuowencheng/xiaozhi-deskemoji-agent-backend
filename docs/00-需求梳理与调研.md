# 小智 deskemoji 个人桌面智能体 · 需求梳理 + 开源调研 + 澄清问题

> 版本 v0.1（第一轮梳理） · 2026-10-02
> 目标：把 ESP32-S3N16R8 deskemoji 从"会聊天的玩具"改造成**你的统一语音出入口**——
> 你说话 → 小智理解 → 下发任务给 WorkBuddy / Codex → 干完活 → 小智主动告诉你。

---

## 一、一句话理解你要的东西

```
你的嘴
  ↓ 语音
deskemoji（ESP32-S3 + 麦 + 喇叭 + OLED + 双舵机 + PAJ7620U2 手势）
  ↓ Websocket / MQTT+UDP
大脑（小智后台：ASR + LLM + TTS + 记忆 + 意图识别）
  ↓ MCP（工具调用）
本机 Windows 桥接服务（常驻）
  ↓ 调度
WorkBuddy / Codex / 浏览器 / 文件系统 / 系统命令
  ↓ 结果回流
大脑摘要 → TTS → 小智主动播报「活干完了」+ 表情/舵机联动
```

关键点：**闭环必须是双向异步的**。现在很多项目只做到"下发"，做不到"干完主动回来说一声"。这是你要的差异化，也是现有开源方案最大的缺口。

### 2.4 现有方案的五个共性不足（= 你的改造空间）

1. **没有"回执闭环"**：工具调用都是同步阻塞的，模型等结果→超时。长任务（Codex 改代码这种分钟级）根本跑不了。缺"任务队列 + 状态机 + 完成回调 + 主动 TTS"。
2. **没有真正的记忆层**：服务端顶多有个"本地总结记忆"（把对话压缩成摘要）。你要的"记住我是谁、我的项目上下文、上次干到哪"——需要外挂长期记忆（文件/SQLite/向量库），没人做。
3. **权限没有边界**：49 个工具里含"任意 Shell""全盘读写""屏幕截图外传"。这在 xiaozhi.me 云链路下等于把你的电脑敞开给云端。必须做**白名单 + 危险操作二次确认 + 本地不出网**。
4. **硬件能力没有被抽象**：手势只用来拨舵机，OLED 只显示表情。它们完全可以作为**状态指示器**（任务进行中=思考表情，完成=开心+点头，失败=难过+摇头）——这块几乎没人做，是你最容易做出彩的地方。
5. **工程化缺失**：单点 Python 脚本、无守护、无日志、无鉴权、无 OTA 版本管理。

## 三、仓库组织建议（对应你需求 6）

### ⚠️ 先说一个必须避开的坑

> **GitHub 上 fork 的可见性不能高于父仓库**——公开仓库的 fork 只能是公开的。
> 所以「fork 一份上游再设为私有」这条路**走不通**。
>
> ✅ 正确做法：`git clone --bare` 上游 → `git push --mirror` 到你的私有仓库 → 本地保留两个 remote
> （`origin` = 你的私有仓，`upstream` = 上游公开仓），需要同步时手动 `git fetch upstream && git merge`。
> 代价：失去 GitHub 的 "Fork" 标识和 PR 能力，换来真正的闭源。**对你这个阶段，闭源优先，值得。**

### 推荐结构：**单体私有仓库（monorepo）+ 后期再拆**

前期接口天天变，submodule 会变成拖累。建议：

```
xiaozhi-deskemoji-agent/          ← 单个 private repo（GitHub）
├── README.md                     ← 总索引 + 架构图 + 里程碑
├── docs/
│   ├── 00-需求梳理与调研.md       ← 本文档
│   ├── 01-系统架构与协议.md
│   ├── 02-硬件清单与引脚映射.md
│   ├── 03-固件编译与刷写.md
│   ├── 04-服务端部署.md
│   ├── 05-本机桥接设计.md
│   └── 09-排障速查.md
├── hardware/                     ← BOM、引脚图、串口探测脚本（i2c scan / esptool）
├── firmware/                     ← mirror 自 TranBinh2311 + Maggotxy，保留 upstream remote
├── server/                       ← mirror 自 xinnan-tech/xiaozhi-esp32-server
│   └── plugins/agent-bridge/     ← ⭐自研：任务队列 + 回执 + 主动播报插件
├── bridge/                       ← ⭐自研核心：Windows 常驻桥（MCP Server）
│   ├── mcp_pipe.py               ← wss ↔ stdio 哑管道
│   ├── server_agent.py           ← 工具注册 + 权限白名单
│   ├── dispatchers/              ← workbuddy / codex / browser 适配器
│   ├── memory/                   ← 长期记忆（SQLite + Markdown）
│   └── start.cmd / start.vbs     ← 用户双击启动（⚠️ 不能由 AI 拉起）
└── .github/ISSUE_TEMPLATE/       ← 用 issue 做任务拆分与追踪
```

**任务拆分用 GitHub Issues + Milestone**（而不是建一堆 repo）：`task/固件升级`、`task/自建后台`、`task/桥接闭环`、`task/记忆层`、`task/硬件扩展`。成熟后再把 `bridge/` 独立成公开仓库。

## 四、必须你来拍板的澄清问题（请逐条回我）

### A. 路线与边界（决定整个架构，最关键）

- **A1｜后台路线**：① 继续用 xiaozhi.me 云 + 官方 MCP 接入点（最快，1–3 天见效，但语音/截图要过公网、能力受限）；② 直接自建 xiaozhi-esp32-server（完全自控，1–2 周，可离线）；③ **先①打通闭环再迁②**（我推荐）。你选哪个？
- **A2｜权限边界**：允许小智操作电脑到哪一步？请在下列里勾：
  `[ ] 只读查询（读文件/查进程）` `[ ] 启动/切换应用` `[ ] 控制浏览器` `[ ] 写文件` `[ ] 执行指定白名单命令` `[ ] 任意 Shell` `[ ] 让 Codex 改代码并自动提交`
  哪些动作**必须**语音二次确认？
- **A3｜网络与在线**：设备放家里还是公司？电脑会关机/休眠吗？如果设备在家、电脑在公司，走公网中转还是只做局域网？要不要 24 小时在线（那后台得放云或 NAS）？
- **A4｜隐私红线**：语音、屏幕截图、文件内容是否会经过第三方服务器——你能接受到什么程度？（这条直接决定 A1 里②是不是 P0）

### B. 硬件现状（决定我能不能"连上去扫一遍"）

- **B1｜当前固件版本**：oshwhub 附件有 `gesture-music2.0.1.3` / `gesture2.0.5` / `2.0.5`，你板子上刷的是哪个？有没有备份原厂 bin？
- **B2｜手势模块**：PAJ7620U2 焊上/插上了吗？INT 引脚是留空还是接了？（教程说留空，接了会有中断模式可玩）
- **B3｜舵机**：SG90 还是 MG90S？水平+垂直两路都装了吗？云台是 FPV 双轴那款吗？
- **B4｜连线状态**：现在设备 USB 插在这台电脑上吗？设备管理器里是 COM 几？（我要跑 esptool 读 chip id / flash / mac）
- **B5｜扫描粒度**：你希望我探到什么程度？`芯片/Flash/PSRAM/MAC` + `I2C 设备扫描（OLED 0x3C、手势 0x73）` + `固件版本` + `分区表`，够不够？还是只靠资料推断、先不动硬件？
- **B6｜背景二那批模块**：具体几块、什么型号（ESP32-WROOM / S3 / C3）？你想让它们扮演什么角色——分布式传感器节点？还是将来替换主板？

### C. 记忆与大脑（你需求 1 里"有自己的记忆、自我学习完善"）

- **C1｜"记忆"具体指哪些**？请勾：
  `[ ] 对话记忆（记得昨天聊过啥）` `[ ] 用户画像（我的习惯/偏好）` `[ ] 项目上下文（我在做哪些项目、进度）` `[ ] 知识库（我的文档/台账可检索）` `[ ] 任务记忆（干过什么活、结果存在哪）`
- **C2｜记忆存哪**：本机文件/SQLite（简单、不出网）？还是云端数据库（可多端）？要不要向量检索（语义搜旧对话）？
- **C3｜后台跑在哪**：本机 Windows？云服务器？NAS？需要 7×24 吗？
- **C4｜大模型**：继续用 xiaozhi.me 提供的（Qwen 实时等），还是自接 DeepSeek / 通义 / 本地 Ollama？

### D. 与 WorkBuddy / Codex 的对接（你需求 3）

- **D1｜WorkBuddy 怎么调**：① 本机 MCP 暴露 ② CLI（`codebuddy -p`）③ HTTP API。
  ⚠️ 提醒：本机已有踩坑记录——引擎凭据是 App 注入的环境变量、端口是动态的、AI 沙箱拉起的进程会被回收，**桥必须由你双击启动**，我不能替你挂后台。
- **D2｜Codex**：`codex` CLI 装了吗？什么版本？登录态还在吗？
- **D3｜回执机制**（最重要）：任务完成后怎么让设备知道？① 轮询（简单、有延迟）② Webhook 回调 ③ **服务端主动音频下发**（Go 版有现成实现，推荐移植）。
- **D4｜一句话触发多个 Agent**：要不要并行？结果太长时是摘要播报还是写文件+口头提示？

### E. 工程与节奏

- **E1｜仓库**：上面 monorepo 方案你认可吗？私有仓库叫什么名字（`xiaozhi-deskemoji-agent`？）？要我现在就建并推第一版文档吗？
- **E2｜节奏**：我建议 P0 = 「语音 → 本机桥 → WorkBuddy 干活 → 小智播报完成」最小闭环，其余（记忆层、硬件扩展、固件升级）排后。你同意吗？还是想先做硬件扫描？
- **E3｜投入**：你每天能在这事上花多久？希望几天内看到第一个能跑的版本？
- **E4｜交付习惯**：要我每完成一步就写一个 `docs/NN-*.md` 并同步 GitHub 吗？还是攒一批再推？

## 六、安全红线（我自己会守，也请你确认）

1. MCP 接入点 token、引擎凭据 **只写本机 `.env`**，绝不进仓库（`.gitignore` 已备）。
2. 桥接只暴露**必要工具**，任意命令执行类接口默认关闭、走白名单。
3. 涉及刷机：**先备份原厂固件**再动手，操作前我会把步骤列给你确认。
4. 任何"删文件/改系统/提交代码"类操作，默认要求语音或界面二次确认。
