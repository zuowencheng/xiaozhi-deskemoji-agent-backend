# 现状盘点：与 xiaozhi.me 在线版 / 开源项目三方对比（2026-10-03）

> 主人三个问题：
> 1. 现在的小智能不能媲美 xiaozhi.me 在线版？
> 2. 之前参考的 Python 开源项目有哪些功能？现在后台到底什么样？
> 3. 目标是"新需求 + 保留原有 + 借鉴开源"三合一吗？
> 4. 屏幕是彩色还是黑白？能切版本吗？

---

## 一、先说屏幕：**0.96 寸单色 OLED，硬件决定，切不了**

| 项 | 事实 | 证据 |
|---|---|---|
| 驱动 | **SSD1306**，128×64 | `main/boards/esp32-s3n16r8-emoji/config.json` → `CONFIG_OLED_SSD1306_128X64=y` |
| 接口 | **I2C**（2 根线） | `emoji_board.cc::InitializeDisplayI2c()`，SDA/SCL 各 1 脚 |
| 尺寸 | 0.96 寸 | 原项目 BOM 明确写"0.96寸OLED显示屏模块4针 SSD1306" |
| 颜色 | **单色**（16 级灰阶） | SSD1306 物理上就没有彩色像素 |

**网上看到的"蓝黄色眼睛"是渲染图 / 宣传图，不是这块硬件的真实显示。**

### 能不能改成彩屏？——理论可行，但代价很大

要换成 1.3" ST7789 彩屏（240×240，65K 色），需要：

| 项 | 现状 | 彩屏要求 | 难度 |
|---|---|---|---|
| 驱动芯片 | SSD1306 | ST7789 | 换 LVGL 显示驱动，重写初始化 |
| 接口 | I2C（2 脚） | **SPI（6 脚**：MOSI/SCK/CS/DC/RST/BL） | 引脚要重新分配 |
| PCB | 原版 4 针排线口 | 物理上插不上 | **要改 PCB 或飞线** |
| 分区 | assets 7M | 彩图资源占空间大 | 表情资源重做 |
| 工作量 | — | — | **不是切版本，是硬件改造 + 大改固件** |

**结论：不建议。** 除非你想要"真正的桌面宠物"那种彩色脸，
否则 128×64 单色屏 + 舵机 + 手势的组合已经是这个硬件的合理形态。

> 想低成本试彩屏，可以买 1.3" ST7789 模块飞线接到空脚上，
> 但那是**另一个项目**，不是"切个版本"。

## 二、后台到底什么样：现在只有一个页面，**http://192.168.3.139:8005/**

### 2.1 端口地图

| 端口 | 用途 | 有页面吗 |
|---|---|---|
| **8005** | **自研管理台**（唯一有页面的） | ✅ HTML |
| 8000 | WebSocket 设备长连接 | ❌ 协议端点 |
| 8003 | OTA 固件接口 | ❌ HTTP 接口 |
| 8004 | 主动播报 / 定时提醒 | ❌ 只有 POST 接口 |

### 2.2 8005 页面逐块说明

| 区块 | 内容 |
|---|---|
| **服务状态** | 4 个端口的监听状态 + PID；**「启动后台 / 停止后台 / 刷新」三个按钮** |
| **设备** | 在线设备列表（MAC），没设备时提示"对它说一句你好小智就会上线" |
| **配置** | 23 个可调项（下表），改完点「保存配置」，**需重启后台生效** |
| **投递箱** | bridge 目录下的任务/提醒清单 |
| **服务日志 / 错误日志** | 各取尾部若干行，排查时不用开编辑器 |

### 2.3 可调项清单（`server/admin/admin_server.py` 的 `EDITABLE`）

共 **23 项**（`EDITABLE` 实际值；本文此前写 15、docs/20 写 11，2026-10-04 统一校准为 23）。

| # | 分组 | 项 | 当前值 |
|---|---|---|---|
| 1 | 引擎 | LLM | DeepSeekLLM |
| 2 | 引擎 | ASR | DoubaoASRStream |
| 3 | 引擎 | TTS | HuoshanV3TTS |
| 4 | 引擎 | Memory | nomem |
| 5 | 语音 | rate（语速%，仅 EdgeTTS 生效） | 未设置 |
| 6 | 语音 | pitch（音调 Hz） | 未设置 |
| 7 | 语音 | speed_ratio（语速倍率，火山生效） | 未设置 |
| 8 | 交互 | play_sound_after_reply（说完播提示音） | true |
| 9 | **打断** | **min_silence_duration_ms** | **700** |
| 10 | **打断** | **threshold_low** | **0.3** |
| 11 | 连接 | close_connection_no_voice_time | 86400 |
| 12 | 连接 | enable_websocket_ping | true |
| 13 | 交互 | enable_greeting | true |
| 14 | 交互 | enable_wakeup_words_response_cache | true |
| 15 | 交互 | enable_stop_tts_notify | false |
| 16 | 超时 | tool_call_timeout | 30 |
| 17 | 超时 | tts_timeout | 15 |
| 18 | 交互 | listening_timeout_sec（聆听超时，握手下发设备） | 180 |
| 19 | 免打扰 | quiet_hours_enabled | false（默认关） |
| 20 | 免打扰 | quiet_hours_start | "23:00" |
| 21 | 免打扰 | quiet_hours_end | "07:00" |
| 22 | 免打扰 | todo_speak_start（待办提醒可播起点） | "07:00" |
| 23 | 免打扰 | todo_speak_end | "22:00" |

> ⛔ 时间值必须带引号：`23:00` 裸写会被 YAML 1.1 解析成六十进制整数 `1380`。

> ⚠️ 打断那两项此前记的 `1400 / 0.1` 是**无依据的实验值**，已回退官方默认 `700 / 0.3`
> （详见 docs/41）。另外 `threshold_low` 在 `EDITABLE` 里被误标成 `int`，
> 它是 0~1 的浮点，已从 `int` 改为 `float`，否则在管理台改它会被截成 0 或 1。

> ⚠️ 固件里的 `vad_min_noise_ms` 管理台改不了（编译期常量），要改必须刷机。

## 三、那个 Python 开源项目——**我们用的就是它**

**必须澄清一件事**：`server/xiaozhi-server/` 就是 `xiaozhi-esp32-server`（Python 版）
的 **server-only 模式**源码本体，不是"参考"，是**直接用的**。

那个项目有**两种部署模式**：

| | Server-Only 模式（**我们的**） | Full-Module 模式（没装） |
|---|---|---|
| 组成 | `xiaozhi-server`（Python） | + `manager-web`(Vue3) + `manager-api`(Java) + MySQL + Redis |
| 管理界面 | **无**（所以我们自己写了 8005） | **Web UI @ 8002** |
| 存储 | `.config.yaml` 文件 | MySQL `sys_params` 表 |
| 多用户 | ❌ | ✅ |
| 角色管理 | 单条 prompt | 多 agent / 每用户独立 |
| 声音克隆 | ❌ | ✅ 上传音频克隆 |
| 声纹识别 | ❌ | ✅ 注册识别 |
| 知识库 | 文件配置 | ✅ 文档管理 RAG |
| OTA 管理 | 只发文件 | ✅ 数据库版本管理 |
| 内存 | 2~4GB | 4~8GB |

### 3.1 开源项目完整功能清单 vs 我们现状

| 功能模块 | 开源项目 | 我们 | 说明 |
|---|---|---|---|
| 流式 ASR | ✅ 多家 | ✅ **SherpaASR（本地）** | 已装 14 个 provider，可换 |
| 流式 TTS | ✅ 多家 | ✅ **Edge 晓晓** | 已装 17 个 provider，火山待开通 |
| VAD | ✅ Silero | ✅ 已调至 1400ms | |
| 声纹识别 | ✅ 3D-Speaker | ❌ **没开** | 日志一直报"声纹识别URL未配置" |
| 视觉感知 VLLM | ✅ 多家 | ⚠️ 有 provider **没配** | 有摄像头才能用 |
| 意图识别 | ✅ function_call | ✅ | |
| 记忆系统 | ✅ 3 种 | ⚠️ 官方 `nomem`，**自研 bridge** | 自己那套更好用 |
| **电脑控制** | ❌ 没有 | ✅ **16 个工具** | ★ 我们独有 |
| **主动播报** | ⚠️ 靠 MCP 指令绕 | ✅ **原生 HTTP 接口** | ★ 我们独有 |
| 定时提醒 | ❌ 没有 | ✅ | ★ 我们独有 |
| 舵机/表情/手势 | ❌ 没有 | ✅ | ★ 硬件独有 |
| 知识库 RAGFlow | ✅ | ⚠️ 代码在，**没配** | |
| MQTT 指令下发 | ✅ | ❌ | 单设备用不上 |
| 声音克隆 | ✅（Full 模式） | ❌ | 火山可做 |
| **Web 管理台** | ✅ 8002 全功能 | ⚠️ **只有自研 8005 简易版** | ← 最大差距 |
| 插件热加载 | ✅ | ✅ | |
| 性能测试工具 | ✅ test_page.html | ❌ | |

## 四、能不能媲美 xiaozhi.me？——**分两半看**

### 4.1 ✅ 对话体验：已经媲美，部分反超

| 维度 | xiaozhi.me | 我们 |
|---|---|---|
| 识别准确率 | 云端 ASR | 本地 Sherpa（**开火山流式 ASR 后可反超**） |
| 音色 | 免费但**只有他们定的那几个** | Edge 晓晓（免费+可选更多）/ 火山小何2.0（付费可选） |
| 语速调节 | ✅ | ✅ 管理台已支持 |
| 打断松紧 | 固定 | ✅ **可调，比官方宽松** |
| 唤醒提示音 | 有 | ✅ 已修（刚做的） |
| 主动播报 | 需绕 MCP | ✅ **原生接口，已验证出声** |
| 电脑控制 | ❌ | ✅ **16 个工具** |
| 舵机/表情/手势 | ❌ | ✅ |
| 隐私 | 数据上云 | **局域网内，不出网** |

### 4.2 ❌ 云端生态：我们确实没有

| 缺失 | 影响 | 值不值得补 |
|---|---|---|
| **完整 Web 管理台** | 配置要走 yaml + 重启，不方便 | ★★★ 最该补 |
| 声纹识别 | 分不清谁在说话 | ★★ 多用户才有意义 |
| 视觉感知 | 看不到摄像头 | ★★ 你没提过摄像头 |
| 知识库 RAGFlow | 喂文档问答 | ★★★ 看你需求 |
| 声音克隆 | 用你的声音 | ★★ 火山 8元/万字符 |
| 多用户/多设备 | 一台设备用不到 | ❌ 无意义 |

## 五、目标确认：是的，就是三合一

你说的目标我复述一遍确认：

```
① 新增需求（主动播报 / 电脑控制 / 定时提醒 / 舵机表情）
        ＋
② 保留小智原有（对话 / 唤醒 / 表情 / 音乐 / 音量 / OTA ...）
        ＋
③ 借鉴开源项目（多引擎可换 / 插件系统 / 记忆 / 知识库 ...）
```

**这个目标是对的，而且已经完成了大半。** 剩下没做的按优先级：

| 优先级 | 待补 | 理由 |
|---|---|---|
| ★★★ | 8005 管理台补齐（角色、人格、知识库开关） | 现有配置项还是硬编码在 yaml |
| ★★★ | 接火山流式 ASR 2.0 | 识别准确率是硬指标 |
| ★★ | 知识库 RAG（已有代码，没配） | 喂文档 |
| ★★ | 记忆系统换回官方 `mem_local_short` | 对比自研 bridge 哪个好 |
| ★ | 声纹 / 视觉 / 声音克隆 | 看你需求 |
