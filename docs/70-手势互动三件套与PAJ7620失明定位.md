# 70 · 手势互动三件套上线 + PAJ7620 失明定位（2026-10-13）

## 背景
主人反馈三点：①舵机会动但不跟手势；②做手势时想要即时反馈，确认设备在交互；③想用手势直接触发聆听/语音互动。

## 代码级归因（读码结论）
1. **手势与自动动画抢舵机，无仲裁**：手势任务（`GestureTaskFunction`）直接调 `servo_controller_->HeadLeft()` 同步写角度；自动动画（`AnimationTask`→`ExecuteLookLeftAnimation` 等）也直接写同一个舵机。表情队列有 `is_animating_` 互斥，但**舵机本身没有任何互斥**，同时跑就角度写乱，表现就是"舵机在动但不跟我"。
2. **手势反馈会被吞**：手势的表情走 `PlayAnimation` 队列，撞上 `is_animating_` 直接丢弃（"已有动画正在执行，跳过此次动画"）。
3. **向前手势的聆听功能留了线没接**：`gesture_sensor.cc` GESTURE_FORWARD 分支只有注释 `// start_chat = true;`，`Application::StartListening()` 是现成接口（唤醒词按钮同款）。

## 修复（一版全上，ELF `e0a66cca4`，2766096 字节，刷 ota_1）
1. **舵机仲裁层**：`ServoController` 加递归互斥锁（`xSemaphoreCreateRecursiveMutex`，递归是因为手势持锁后调的 `HeadLeft()` 内部还会过 `SetServoAngle`）。手势处理全程持锁；自动动画 `SetServoAngle` 50ms 抢不到锁即返回 false，调用方循环 break 让位。拿不到锁也照做（最坏退化为旧行为）。
2. **反馈提级**：`AnimationMessage` 加 `priority`；priority 消息 `xQueueReset` 清队 + `xQueueSendToFront` 插队首；AnimationTask 对 priority 无视 `is_animating_`。
3. **向前推 = 聆听开关**：`gesture_sensor.cc` include `application.h`，GESTURE_FORWARD 分支读 `GetDeviceState()`：非聆听态 `StartListening()`（speaking 自动打断播报），聆听态再推 `StopListening()` 回待机。
4. **顺带**：PAJ7620 初始化序列补 `{0xEF,0x00}` 切回 bank 0（上游缺陷：序列结尾停在 bank 1，手势 flag 在 bank 0）；方向映射修正（曾整个反了）；诊断心跳每 5 秒打 flag0/1 + 接近状态(0x6B) + 接近原始值(0x6C) + 状态指示(0x45)。

## PAJ7620 失明定位（未完结，等硬件实验）
三段对照实验（手离 10s / 手放 5cm 静置 10s / 挥手 15s）：
- flag0/flag1 全程 0x00，**接近状态 0x00、接近原始值全程 0**、状态指示 0x02 全程不动
- I2C 读取零失败（芯片正常应答）→ 排除排线断裂、芯片死亡
- **判定：红外发射/接收层面失明**。最大嫌疑：当天新换的 USB 口供电偏弱（PAJ7620 靠内置 IR LED 主动发光，供压即瞎；换口前灵敏、换口后失灵，时间线吻合）
- 待办：插回原 USB 口（或手机充电头独立供电）复测；若恢复则固定该口，若仍 0 再查排线/换模块
