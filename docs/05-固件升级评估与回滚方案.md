# 05 · 固件升级评估与回滚方案（2026-10-02 调研结论）

## 一句话结论

**现在不建议升级。** 投入产出比太差，而且会打断刚跑通的闭环。但**回滚保障必须先做好**（已完成，见下文），这是任何时候动固件的前提。

## 现状 vs 上游

| 项 | 实际情况 |
|---|---|
| 你的固件 | 版本 **2.0.1**，项目名 xiaozhi，编译于 **2026-01-16**，ESP-IDF v5.5.1，运行在 ota_0 |
| 你的板型 | `esp32-s3n16r8-emoji`（社区自制板「赛博太白」），板级代码在 `main/boards/esp32-s3n16r8-emoji` |
| 上游固件仓库 | `78/xiaozhi-esp32`，最新 **v2.5.0**（2026-09-10），提供各板型预编译 zip |
| 你的固件来源 | `TranBinh2311/xiaozhi-deskemoji-gesture-music-taibai`，**只有 1 次提交（2026-06-28），已停更** |

## 三个决定性事实（都是实测查出来的）

**1. 官方没有你这个板型。** 在 `78/xiaozhi-esp32` 全仓库搜 `emoji`，只出来 `otto-robot`、`electron-bot`、`esp-hi` 这几个官方板的 emoji 显示代码，**没有 `esp32-s3n16r8-emoji`**。所以 v2.5.0 那堆预编译 zip 里不会有你板子的份——**不存在"下载下来直接刷"这条路**。

**2. 你的固件是社区魔改版，不是官方原版。** 它多了手势识别（PAJ7620U2）和音乐功能。直接刷官方任何版本 = **这两个功能全没了**，除非把社区那部分代码移植过去。

**3. 本机没有编译环境。** 实测 `idf.py`、`cmake`、`ninja`、`xtensa-esp32s3-elf-gcc` **全部 NOT FOUND**，`IDF_PATH` 为空，`C:\Espressif` 不存在。也就是说升级前要先从零装 ESP-IDF（几 GB 下载 + 工具链，20~60 分钟量级）。

## 升级要付出的代价

1. 装 ESP-IDF 工具链（几 GB，1 小时量级）
2. 拉官方 v2.5.0 源码
3. **移植板级代码**：把 `esp32-s3n16r8-emoji`、手势模块、音乐功能搬到新代码树上——v2.0.1 到 v2.5.0 跨了 5 个次版本，API 大概率变过，这是最容易翻车的一步
4. 编译 → 刷 ota_1 → 逐项验证（屏幕、麦克风、扬声器、手势、舵机、联网、唤醒）
5. 出问题就回滚重来

## 为什么现在不值得

- **对你当前目标没有直接帮助**。你的闭环是「小智 → 云端 → MCP → 本机桥 → WorkBuddy」，固件只负责采集语音和播报，2.0.1 已经干得很好（今天实测照实念出了 CPU 和内存）。
- **会引入第二个变量**。闭环刚跑通就动固件，出问题分不清是桥的问题还是固件的问题——这种亏我吃过。
- **收益是"上游新功能"**（更多板型支持、协议更新等），对你个人使用场景基本无感。

**建议时机**：等阶段二自建后台时一起做；或者哪天你明确需要 v2.5.0 的某个具体功能再动。

## 回滚方案（已做好，随时可用）

产物在 `hardware/reports/rollback_kit/`，由 `hardware/make_rollback_kit.py` 生成：

| 文件 | 用途 |
|---|---|
| `ota_0_app.bin` | 当前运行固件（4MB），从 0x100000 读出 |
| `otadata.bin` | 启动分区标记（8KB），从 0xD000 读出 |
| `nvs.bin` | 配网 / 激活信息（16KB），从 0x9000 读出 |
| `rollback_app.cmd` | **只回滚 app**，约 10 秒（日常首选） |
| `rollback_full.cmd` | 全片回滚 16MB，约 2~3 分钟（救砖用） |
| `monitor.cmd` | 串口看启动日志，判断新固件有没有起来 |

**三层保险**：

1. **A/B 分区**：你的 ota_1（0x500000，4MB）**目前是空的**，新固件刷进去就能双分区并存，切换只改 otadata
2. **一键回滚**：`rollback_app.cmd` 10 秒回到现在这个状态
3. **救砖**：真刷到连 bootloader 都起不来，按住 **BOOT 键**再插 USB 进下载模式，跑 `rollback_full.cmd` 全片恢复

另外 `hardware/reports/backup_20261002_16MB.bin` 是 16MB 全片备份（**建议再拷一份到移动硬盘**，它只躺在本机，且被 gitignore 排除）。

## 如果哪天真要升，步骤

1. 装 ESP-IDF（版本以官方 v2.5.0 的 README 要求为准）
2. `git clone` 官方 v2.5.0 + 社区仓库
3. 移植 `esp32-s3n16r8-emoji` + 手势 + 音乐
4. 编译出 `xiaozhi.bin`
5. `esptool write-flash 0x500000 xiaozhi.bin`（刷到空的 ota_1，**别覆盖 ota_0**）
6. 切换 otadata 到 ota_1，重启
7. 逐项验证；不对就 `rollback_app.cmd`
