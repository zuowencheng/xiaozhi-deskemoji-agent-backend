## 三、⭐ 关键发现：能拿到**精确**计费字符数

火山 v3 支持一个请求头：

```
X-Control-Require-Usage-Tokens-Return: *
```

加上后，**响应体最后一块**会返回真实计费字符数：

```json
{"code":20000000,"message":"OK","usage":{"text_words":26}}
```

实测文本长度 26 → `text_words: 26`，**完全一致**。

所以我们的额度账本记的是**真值，不是估算**。这比"数自己发出去多少字"可靠得多
（分句、重试、标点都算不准）。

## 四、`bridge/quota.py` —— 额度账本

存储：`bridge/quota.json`（纯 JSON，人能看能手改）

```json
{
  "channels": {
    "2.0": {"used": 0, "quota": 20000, "alerted_at": 0, "last_at": 0},
    "1.0": {"used": 0, "quota": 20000, "alerted_at": 0, "last_at": 0}
  }
}
```

| API | 作用 |
|---|---|
| `add_usage(ch, chars)` | 累加一次合成的计费字符 |
| `remaining(ch)` | 剩余 / 百分比 / 是否耗尽 |
| `stats()` | 两个通道一览 |
| `need_alert()` | 该提醒的（剩余 <15% 且冷却期已过） |
| `mark_alerted(ch)` | 打提醒戳 |
| **`pick_channel()`** | **按优先级挑还能用的通道**（2.0 优先，耗尽自动落 1.0） |

**降噪设计**：同一条提醒 **6 小时内不重复**（`_ALERT_COOLDOWN`），
阈值 15%（`2.0` = 还剩 3000 字符时开始提醒）。

## 五、provider 改造：`huoshan_v3_http.py`

### 1. 自动选通道
```python
def _resolve_channel(self):
    ch = quota.pick_channel()          # 2.0 有额度就 2.0，没了自动 1.0
    rid = CHANNELS[ch]["rid"]          # rid  一起换
    spk = self.speaker_by_channel[ch]  # 音色 一起换
    return rid, spk, ch
```
`auto_channel: false` 可关掉（固定用配置里的通道）。

### 2. 精确记账
请求加 `X-Control-Require-Usage-Tokens-Return: *`，
从响应最后一块取 `usage.text_words` → `quota.add_usage()`。

### 3. 通道切换时打日志
```
切换到语音合成 2.0 通道：rid=seed-tts-2.0 speaker=zh_female_vv_uranus_bigtts（豆包语音合成2.0已用 0 / 20000 字符，还剩 20000）
```

配置项：`quota_watch_enabled`(true) / `quota_poll_interval`(1800)

## 八、还能再省的地方：发音词典

火山 2.0 支持 `pronunciation_dict`（**最多 5000 条，原词 ≤9 字**），
可以修正专有词的发音——比 ASR 热词表更直接（那是让 AI 听对，这是让 TTS 念对）。

值得加的：
```
小智/(xiao3 zhi1)
WorkBuddy/(wer1k ba4 di1)
deskemoji/(desk emoji)
豆包/(dou4 bao1)
Ollama/(o5 la1 ma1)
```

用法（在 `additions` 里）：
```json
{"pronunciation_dict":{"tone":["小智/(xiao3 zhi1)","豆包/(dou4 bao1)"]}}
```

**建议等额度用完前再决定**——如果换 1.0 通道，2.0 的发音词典就用不上了。
