# 57 · 唤醒后干等 + 乱说「拜拜」：三个 bug 叠在一起

> 时间：2026-10-03 23:43 ~ 23:56
> 现象（主人原话）：唤醒后它问「还没睡」，我说了一句话它就一直聆听不回；
> 过会儿再问，它说「拜拜」；我说我没说过拜拜，它说"那当我没说"。

## 二、三个根因（按责任排序）

### Bug 1 · ASR 一句话被 definite 提前切断（真凶，上游行为）
`core/providers/asr/doubao_stream.py:215-241`：自动模式一收到 `definite=True`
就 `self.text = utterance["text"]` + `handle_voice_stop()` + `break`。

豆包 ASR 会在一句话**说到一半**就给 definite（语义断句），
所以「还没呢你」被判成"上一句已经结束"，后半截随连接关闭蒸发。

铁证：definite 帧 duration=1980，后面 2580/2940 两帧明明带着完整文本。

### Bug 2 · 守卫静默丢弃（我上一轮引入的放大器）
`greeting_guard` 一看"这不就是唤醒词吗"→ `return`，**一句话不说**。
主人只看到屏幕"聆听中"，不知道自己的话被吞了 → 干等 21 秒。

**静默丢弃的代价比多说一个字大得多** —— 这是本次最大的教训。

### Bug 3 · LLM 误触发退出机制（上游 prompt 规则太松）
`agent-base-prompt.txt:11` 上游原文：

> 4. [Exit mechanism] When the user says farewell words like "再见","拜拜","晚安","退下","待机"…

模型收到「为什么不回答我？」，在上下文混乱（问候语"还没睡？"被写进 dialogue
作为 assistant 消息）的情况下**脑补成要道别**，而且只说了告别词、
没有调 `handle_exit_intent`（说了拜拜但设备还在聆听 —— 最怪的状态）。

## 三、修复

| # | 文件 | 改动 |
|---|---|---|
| 1 | `core/providers/asr/doubao_stream.py` | 新增 `_collect_remainder()`：definite 后开 1.2s 续接窗口，取累积全文里最长的一条；`last_stream_duration`/超时/出错都安全退回。自动模式不再拿到 definite 就 break |
| 2 | `core/handle/greeting_guard.py` | 返回值 `bool` → `"" / "drop" / "prompt"` 三态。命中后：≤1.5s（唤醒残留）静默丢；>1.5s（主人明明开口了却只听清唤醒词）→ 播一声「嗯？」提示重说 |
| 2b | `core/providers/asr/base.py` | 新增模块级 `_speak_live()`（照抄 listenMessageHandler 的 TTS 直播分支，不 send_stt、不进 LLM）；按 verdict 分派 |
| 3 | `agent-base-prompt.txt:11` | 退出机制改成严格触发：只认主人**这一轮原话里明确出现**的告别词；抱怨/质问/沉默/自己想收尾**一律不许道别**；不许翻旧账自我纠错；说了告别必须同时调 handle_exit_intent |

## 五、留下的经验

1. **静默丢弃 = 让用户对着空气等**。任何"这条输入我不处理"的分支，
   要么给反馈，要么保证它不可能误伤真实输入 —— 二者至少占一条。
2. **ASR 的 definite ≠ 人说完了**。语义断句和 VAD 结束是两个概念，
   上游拿 definite 当结束符是有代价的。
3. **模型"自我纠错"式的回答（"是我多嘴了""那当我没说"）= 它已经串线了**，
   不要当成偶发幻觉，去查上下文里是谁塞进去的。
