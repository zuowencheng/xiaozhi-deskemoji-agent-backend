## 一、说话慢被打断 —— 固件 VAD 静音判定只有 100ms

**根因**：`main/audio/processors/afe_audio_processor.cc:43`

```cpp
afe_config->vad_min_noise_ms = 100;   // ← 静音满 100ms 就判定"说完了"
```

AFE 一旦判定"语音结束"，就把音频送识别、设备停止收音。
说话中间停顿超过 **0.1 秒**就被切断 —— 正常语速的一句话里，词与词之间停顿常有 0.2~0.4 秒，
所以"稍微慢一点"必被切。

**修复**：`100` → **`800`**（毫秒）。

| 值 | 效果 |
|---|---|
| 100（原） | 极灵敏，正常说话都会被切断 |
| **800（现）** | 句中停顿 0.5~0.8 秒都不切，说完约 0.7 秒后开始识别 |
| 600 | 偏灵敏，适合说话快的人 |
| 1000 | 非常宽容，但说完后等待明显 |

> 这是"留间隙"的必要代价：判得宽容 = 说完后要多等一会儿。
> 觉得等太久就把这个值往下调。

**注意**：这是**固件参数，改完必须重新编译刷机**，管理台改不了。

## 二、唤醒后没有提示音 —— 提示音被 `#else` 分支吃掉了

**根因**：`main/application.cc` 的 `OnWakeWordDetected()`

```cpp
#if CONFIG_USE_AFE_WAKE_WORD || CONFIG_USE_CUSTOM_WAKE_WORD
    protocol_->SendWakeWordDetected(wake_word);
    SetListeningMode(...);          // ← 这条路径【没有】PlaySound
#else
    SetListeningMode(...);
    audio_service_.PlaySound(Lang::Sounds::OGG_POPUP);   // ← 提示音只在这
#endif
```

本机唤醒词 `wn9_nihaoxiaozhi_tts` 走的是 **AFE 唤醒词**（`CONFIG_USE_AFE_WAKE_WORD`），
所以那句 `PlaySound(OGG_POPUP)` **从来没执行过** —— 不是没做，是被编译分支挡住了。

**修复**：把 `PlaySound` 提到 `#endif` 之后，两个分支都播。

⚠️ **风险提示**：本板无 AEC（`total 1 channels(1 microphone, 0 playback)`），
提示音会被麦克风录进去一点点。所以选的是官方那个最短最轻的 `OGG_POPUP`。
**若实测发现提示音被识别成话、或干扰首句识别**，把 `application.cc:676` 那行注掉即可。

## 三、语速 / 音调 —— 服务端本来支持，只是没写进配置

Edge TTS provider（`core/providers/tts/edge.py`）早就读 `rate` / `pitch`：

```python
speech_rate = config.get("rate", "0")
self.edge_rate = f"{self.speech_rate:+}%"
```

只是 `data/.config.yaml` 里没写这两个键，所以一直是默认 0。

**已加进配置**：

```yaml
TTS:
  EdgeTTS:
    voice: zh-CN-XiaoxiaoNeural
    rate: 0     # 语速 %：-100~100，0=正常，-20=慢，+20=快
    pitch: 0    # 音调 Hz：0=默认
```

**已挂进管理台**（`server/admin/admin_server.py` 的 `EDITABLE`），
打开 http://192.168.3.139:8005/ 就能看到"语速/音调"两个输入框，改完重启后台生效。

## 六、Codex「鸟巢本地语音识别」项目评估

路径：`C:\Users\zuowe\Documents\Codex\01-项目\鸟巢本地语音识别`

| 项 | 内容 | 能否复用到小智 |
|---|---|---|
| `models/asr/model.int8.onnx`（81MB）+ `tokens.txt` | Sherpa-ONNX **offline**（非流式）ASR 模型 | ⚠️ 见下 |
| `runtime/sherpa-onnx-offline.exe` | 离线识别可执行文件 | 同上 |
| `runtime/NAudio*.dll` | C# 音频采集库 | ❌ 我们用 ESP32 麦克风 |
| TTS | **没有** | ❌ 无 TTS 可复用 |

**结论**：
- 那个 81MB 模型是 **offline（整段识别）**，小智是**流式边说边识别**，
  架构不匹配，直接换会破坏实时性 —— **不建议复用**。
- 项目里**根本没有 TTS**，所以"有没有比现在更好的 TTS"这条落空。
- 真要提升识别准确率，正路是开**火山豆包流式 ASR 2.0**（已在开通清单里）。
