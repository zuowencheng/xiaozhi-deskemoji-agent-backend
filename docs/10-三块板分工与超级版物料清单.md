## 二、✅ 确认 2：第二块 WROOM-32 定位为「紧凑版小智」

**认可，但要修正一处细节：它不是只有 OLED 一条路，官方给了两种紧凑板型。**

| 官方板型 | target | 屏幕配置 | 对应你手上的件 |
|---|---|---|---|
| `bread-compact-esp32` | **esp32** | `CONFIG_OLED_SSD1306_128X64` | **0.96" OLED 4 脚** 正好 |
| `bread-compact-esp32-lcd` | **esp32** | **`CONFIG_LCD_ST7789_240X240_7PIN`** | ⭐ **1.54" 240×240 彩屏** 正好 |

> 这是本次实测最有用的一条：官方给经典 ESP32 备了 **ST7789 240×240** 的板型，你清单第 11 项的彩屏有原生归宿。

### 这块板要认的限制（无 PSRAM）
- 4MB Flash、无 PSRAM、~520KB SRAM → **跑不了彩屏+摄像头+重 LVGL 的组合**，但「彩屏 + 麦 + 功放」这一档官方明确支持。
- 离线唤醒词（ESP-SR）在无 PSRAM 的经典 ESP32 上很吃紧 → **建议用按键唤醒**（开发板自带 BOOT 键，`bread-compact-*` 系列默认就支持按键触发）。
- 定位：**练手 + 实验台**，主战场仍是 deskemoji 那块 S3N16R8（16MB Flash + 8MB PSRAM）。

### 要补买的件（就两件）
| 件 | 规格 | 大约价 |
|---|---|---|
| I2S 数字麦克风 | INMP441（或 ICS-43434） | ¥8~15 |
| 小喇叭 | 8Ω 1W~2W，最好带腔体 | ¥5~15 |

清单里的 **MAX98357 紫板功放**、**0.96" OLED**、**1.54" 彩屏**、**ESP32 扩展板 30P**、**120 根杜邦线**、**830 孔面包板** 全部可复用。

## 三、❓ 问题 1：1.54" 彩屏给「现在这台小智」可行吗？

### 结论：不建议。**引脚不是主要障碍，屏幕类型 + 固件适配才是。**

先把现在这台（deskemoji / 赛博太白）的引脚占用摊开——这是从社区固件 `board_config.h` 实读的，不是猜的：

| 功能 | 器件 | 引脚 |
|---|---|---|
| I2C 总线（屏+手势共用） | SSD1306 + PAJ7620U2 | **SDA=41 / SCL=42** |
| 舵机 ×2 | MG90S 水平/垂直 | **11 / 12** |
| 按键 ×3 | BOOT / 音量+ / 音量− | **0 / 40 / 39** |
| I2S 麦克风 | INMP441（SD/WS/SCK） | **6 / 4 / 5** |
| I2S 功放 | MAX98357（DIN/BCLK/LRC） | **7 / 15 / 16** |
| 板载 LED | — | **48** |

**共占 14 个 GPIO。** ESP32-S3 有 40+ 个可用 IO，电气上一点不挤。真正的障碍是这三条：

1. **屏幕类型完全不同，不是换根线的事。**
   现在是 **I2C 单色 OLED**（SSD1306 128×64，两线）；1.54" 彩屏是 **SPI 的 ST7789 240×240**，8 针（VCC/GND/SCL/SDA/RES/DC/CS/BLK）。要在板级代码里把显示器类整套换掉（`OledDisplay` → RGB/SPI panel），还要挪引脚。
2. **表情资源全部作废。**
   现在这台的卖点就是 EMOJI 表情动画，**资源是按 128×64 单色屏做的**。换 240×240 彩色屏等于表情全部重做——工作量比换屏本身大得多，而且这台的核心体验（眼睛动画 + 舵机云台）会被打散。
3. **定制 PCB，不是开发板。**
   赛博太白是打样 PCB，空余 GPIO 有没有引到焊盘/排针上是看板子实物的——你说"貌似没有引脚了"，很可能就是板子根本没往外引。这就不是软件能解决的了。
4. 附加风险：app 分区只有 **4MB**，彩色渲染 + 图片资源一上，`idf.py build` 有爆分区风险。

### 这块彩屏更好的两个去处（按推荐度）
1. ⭐ **给 WROOM-32 那台**：官方 `bread-compact-esp32-lcd` 原生支持 `ST7789 240×240`，插上面包板就能用，零适配。
2. **留给超级版**：如果超级版你不想上触摸大屏，1.54" 当状态副屏也合适。

> 一句话：**现在这台已经是一个自洽的闭环（OLED 表情 + 手势 + 云台），别动它。彩屏给新板子，性价比高一个量级。**

## 四、❓ 问题 2：「官方超级版」要买什么

### 4.1 两条实现路线，先选路线

#### 路线 A：买官方已适配的成品（✅ 强烈推荐）
官方 v2.5.0 共 **48 个板型目录**、171 个构建变体，下面这些是**现成能编译、开箱带摄像头/屏/麦**的：

| 板子 | 官方 type | 硬件要点 | 定位 | 参考价 |
|---|---|---|---|---|
| ⭐ **立创·实战派 ESP32-S3** | `lichuang-dev` | 带屏/麦/功放；配置里开 `CONFIG_CAMERA_PSRAM_DMA`（支持摄像头）+ `CONFIG_USE_DEVICE_AEC`（硬件回声消除） | **性价比首选**，官方 README 挂名推荐 | ¥60~100 |
| Waveshare ESP32-S3-CAM | `esp32-s3-cam` | 2.0" / 2.8" / 3.5" 屏 + 摄像头 + AEC，三个变体 | 大屏+摄像头一体 | ¥150~250 |
| M5Stack CoreS3 | `m5stack-core-s3` | 2.0" 触摸屏 + **GC0308 摄像头** + 麦 + 喇叭 + 工业级做工 | 最"超级"的一台 | ¥400 左右 |
| DFRobot df-s3-ai-cam | `df-s3-ai-cam` | OV2640 / OV3660 摄像头，八线 PSRAM | 纯摄像头验证 | ¥150 左右 |
| 乐鑫 ESP32-S3-BOX-3 | `esp-box-3` | 2.4" 触摸屏 + 双麦阵 + 喇叭，AEC | 官方旗舰（**无摄像头**） | ¥300 左右 |

#### 路线 B：自己搭（自由度高，但有个必踩的坑）
- 主控：**ESP32-S3-WROOM-1 N16R8**（16MB Flash + 8MB PSRAM）开发板。**PSRAM 是硬门槛**，没有它摄像头和音频缓冲都吃紧。
- 摄像头：OV2640（约 ¥20）或 OV3660 / OV5640。
- ⚠️ **最大的坑：ESP32-S3 的摄像头走 DVP 并口，约 12~16 根线**（D0~D7 八根数据 + XCLK + PCLK + VSYNC + HREF + SIOD + SIOC + PWDN + RESET）。
  **用杜邦线 + 面包板飞这个接口，几乎必然花屏、掉帧、初始化失败**（走线长、阻抗不匹配、时钟干扰）。
  → 必须买**带 FPC 摄像头座的板子**或**带排线座的摄像头模块**，别指望飞线成功。

> **我的态度：路线 A。** 你手头已经有面包板、杜邦线、传感器一大堆，真正缺的是一台"能当主力、能上摄像头"的机器——买现成的官方适配板，把这半天时间省下来写业务代码，值。

### 4.4 明确**不要**买

- ❌ **AI-Thinker ESP32-CAM**（经典 ESP32、无 PSRAM）——跑小智很勉强，还跟你手上的 WROOM-32 重复。
- ❌ 给经典 ESP32 加彩屏 + 摄像头的组合——芯片本身扛不住。
- ❌ 各种"传感器大礼包"——你手头这 36 项的覆盖面够你玩两年了。

### 4.5 期望管理（两条要说在前面）

1. **官方小智的摄像头是"拍一张传给云端多模态模型看"**，不是本地实时图像识别。ESP32-S3 本地跑不动图像推理，这是能力边界，不是配置问题。
2. **无 PSRAM 的 WROOM-32** 走按键唤醒更稳，别指望它像 S3 那台一样语音唤醒。
